# TASK-research-agents-crew: Подход agents_crew (Rai220) — «сотрудник — это каталог» (role-as-directory + память по специальности)

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- В нашем role-based workflow (процессе по ролям) роли — это файлы-«личности» (`docs/agents/roles/team/*.ru.md`): personality, экспертиза, скиллы. Но у ролей **нет персистентной памяти**: каждый запуск сабагента начинается с нуля, «уроки специальности» не накапливаются, память о проектах размазана по `todo/` и ретроспективам `team-retro/` (которые пишутся про процесс команды, а не про уроки роли).
- Найден репозиторий [Rai220/agents_crew](https://github.com/Rai220/agents_crew) — рабочая схема «команда ИИ-сотрудников», где **сотрудник — это каталог, а не промпт**: `AGENTS.md` (регламент по специальности) + `memory/` (`MEMORY.md`-индекс, `projects/` — один файл на проект, `lessons.md`, `stack.md`) + `journal/`; запуск любым харнесом (claude/codex/free-code/deepagents/kimi) — концепция «мета-харнеса».
- Неизвестно: какие паттерны agents_crew применимы к нашему процессу (память по специальности, lessons, регламент-в-каталоге, консультация соседа) — и что отвергнуть.

### Варианты или путь решения (Solution Sketch)
- Исследовать agents_crew по единой методологии эпика из 8 критериев (тезис, модель процесса, автономия, качество, context engineering, артефакты, маппинг, применяемость).
- Comparison-отчёт в `docs/research/approaches/agents-crew-comparison.md` с маппингом каждого паттерна на артефакты нашего процесса и вердиктом adopt/adapt/reject.
- Отдельно проверить гипотезу тимлида: у наших ролей нет персистентной памяти по специальности (аналога `memory/lessons.md` и `memory/projects/`).

### Ожидаемый результат (Expected Result)
- Comparison-документ `docs/research/approaches/agents-crew-comparison.md` по 8 критериям.
- Строка #2 в сводной таблице `docs/research/approaches-summary.md` (+ тренды/бэклог-рекомендации при наличии).
- Аналитический отчёт в `docs/agents/reports/system-analyst/`.
- Чёткий вердикт: adopt / adapt / reject по каждому паттерну — с обоснованием и оценкой усилий; гипотеза про память ролей подтверждена или опровергнута.

## 8. Comments (Комментарии)
**Резюме содержания репозитория (для контекста исполнителя, НЕ заменяет самостоятельное изучение первоисточника):**

Два привычных способа работы с ассистентом перекошены: треды с общей памятью (помнит всё вперемешку) и «один проект — одна директория» (не знает ничего за пределами репозитория). agents_crew ставит персонажа посередине: память привязана к **специальности** — ML-сотрудник помнит все свои эксперименты во всех проектах, бекендер — свои интеграции, контексты не смешиваются. Скоупы проектов частично пересекаются (у двух сотрудников есть один проект, но заметки разные — каждая держит своё).

Структура сотрудника: `AGENTS.md` (правила и специализация — единственный источник правды) + `CLAUDE.md`-симлинк (для харнесов со своим именем файла) + `memory/MEMORY.md` (индекс, читается в начале каждого запуска) + `memory/projects/` (один файл на проект: путь, зачем, как запускать, грабли, что пробовали) + `memory/lessons.md` (обратная связь создателя и выводы из провалов) + `memory/stack.md` (окружение, доступы, договорённость про секреты) + `journal/YYYY-MM.md` (хронология).

Ключевые свойства: **переносимость** (всё состояние — обычный markdown, сотрудник переезжает `git clone`; «мета-харнес» — харнес расходник), **версионируемость** (личность и память в git), **изоляция** (у каждого своя память, общего хранилища нет намеренно). Главное ограничение: между запусками переносится только записанное в файлы.

Принципы пользования: один сотрудник — одна специальность; обратная связь дороже задачи (поправка «так не делай, потому что…» попадает в `lessons.md`; молча переделанная работа не учит никого); в конце запуска просить записать память; консультация у соседа — запуск его харнесса в его каталоге (`cd ../crew_alfred && claude -p "..."`), глубина ровно один шаг (вызванный сам третьего не зовёт — иначе цена запуска непредсказуема). Вырезано из публичной версии: настоящая память, личность сверх роли (биография не меняет ответы), GUI.

**Гипотеза тимлида к проверке:** у наших ролей нет персистентной памяти по специальности — нет аналога `lessons.md` (уроки роли) и `projects/` (память о проектах роли); `docs/agents/team-retro/` пишется про процесс команды в целом, а не про уроки конкретной специальности; technical-логи `var/log/watch-subagent/` не являются памятью. Подтвердить или опровергнуть по фактическому состоянию — и дать рекомендацию (включая риски: устаревание, конфликт с конвенциями, раздувание контекста).

**Перекличка с нашим процессом (предварительно, требует верификации):** роль-каталог с регламентом ↔ наши файлы ролей `docs/agents/roles/team/*.ru.md` (front matter + personality + экспертиза + мини-чеклист); `CREW.md` «кто есть кто» ↔ RACI-матрица + раздел «Роль» AGENTS.md; консультация соседа ↔ уже есть: тимлид консультируется у ролей через `run-subagent`; «мета-харнес» ↔ наш `AgentRunner`/`run-subagent` над pi/codex (но у нас — программный слой над раннерами, у них — файловая схема над харнесами); `stack.md` с договорённостью про секреты ↔ наш регламент секретов в AGENTS.md; память по специальности ↔ НЕТ прямого аналога (главный кандидат на adapt).
