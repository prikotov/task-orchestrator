# TASK-research-osinara-agent-memory: Техдок Osinara «Как устроена память агента» (три слоя, claims и нити, retrieval, границы доступа)

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Наш проект фактически уже управляет памятью AI-агентов на трёх горизонтах (гипотеза владельца, 2026-11-09): долгосрочная — инструкции и внешние документы (`AGENTS.md`, конвенции, `todo/`-регламент), среднесрочная — задачи `todo/*.todo.md`, краткосрочная — сессия/чат. Модель нигде не сверена с внешними реализациями.
- В треке уже поставлена задача TASK-research-anthropic-agent-memory (статья Anthropic о компонентах памяти). Osinara — **вторая, независимая** точка сравнения: не концептуальная статья, а техническая документация работающей системы долговременной памяти агента (Eve 0.32.0, 15.08.2026): три слоя памяти с разными владельцами и сроками жизни, атомарная запись claim + evidence + нить, локальный retrieval (E5 + pgvector), групповое ревью памяти, границы доступа с HITL-approval.
- Неизвестно: что из реализованных механик Osinara подтверждает или опровергает нашу трёхслойную модель, какие паттерны переносимы в процесс (ретроспективы, `AGENTS.md`-гигиена, handoff) и в дизайн цепочек движка (атомарность шагов, изоляция контекстов, контроль качества заметок).

### Варианты или путь решения (Solution Sketch)
- Первоисточник добыт и зафиксирован: локальная копия `docs/research/orchestration-articles/sources/osinara-agent-memory.pdf` (внешнего URL нет — прецедент книги Ω и учебника «Агентные пайплайны»).
- Исследовать документ по единой методологии эпика из 6 критериев (тезис, паттерн, domain, failure handling, маппинг, применяемость). Документ на русском, 16 страниц, читается напрямую; скилл knowledge-extraction при доступности — для верификации цитат.
- Маппинг на две плоскости: (а) наш процесс управления памятью ролей — слои `AGENTS.md`/конвенций, задачи `todo/`, сессии, ретроспективы + `RETRO-ROADMAP.md`; (б) движок — атомарность записи (пересечение с находками pi-durable), непрозрачные ссылки вместо ID (изоляция контекстов), «внешние данные — недоверенные» (правила working memory из orchestrator-tax), групповое ревью памяти (наш dreaming-контур).
- Вердикт apply / study / skip по каждому компоненту.

### Ожидаемый результат (Expected Result)

Тема: подсистема долговременной памяти агента — три слоя памяти (активный контекст хода / журнал переписки timeline / долговременные claims с нитями), путь записи в одной атомарной транзакции PostgreSQL, чанкинг и локальная эмбеддинг-индексация, чтение (поиск · профиль · нити), групповое ревью памяти, границы доступа (личная/семейная/групповая области, sensitivity, HITL-approval).
