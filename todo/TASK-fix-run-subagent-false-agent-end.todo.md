# TASK-fix-run-subagent-false-agent-end: Ложное срабатывание `agent_end` по подстроке в `watch-subagent.sh`

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
Скрипт делегирования сабагентов `watch-subagent.sh` решает, что pi-агент завершил работу, по наивной проверке подстроки `agent_end` во всей JSON-строке события. Если сабагент читает файл, в тексте которого встречается слово `agent_end` (документация, ретро, исходники), скрипт ложно считает запуск завершённым, перестаёт читать канал событий и уходит ждать процесс. Агент продолжает писать события, буфер FIFO (64 КБ) переполняется, запись блокируется — возникает взаимная блокировка, и запуск убивается по stall-timeout с потерей всей работы. Это блокирует делегирование любых задач, требующих чтения 15 известных файлов репозитория, и воспринималось ранее как «нестабильность модели glm».

### Варианты или путь решения (Solution Sketch)
Заменить проверку подстроки на якорную проверку топ-уровневого поля события: строка события должна начинаться с `{"type":"agent_end"`. Как защита в глубину — осушать канал событий во время ожидания процесса, чтобы агент никогда не блокировался на записи даже при других ошибках классификации.

### Ожидаемый результат (Expected Result)
Запуск сабагента, читающего файлы с текстом `agent_end` внутри, корректно дорабатывает до настоящего события завершения: успех — exit 0 и финальный текст агента, а не взаимоблокировка и убийство по stall. История запусков перестаёт содержать ложные `runner_failed_after_agent_end` для таких сценариев.

## 1. Концепция и Цель (Concept and Goal)
### История (Job Story)
> **Job Story:** Когда сабагент читает файлы репозитория, содержащие слово `agent_end` в тексте, я хочу, чтобы `watch-subagent.sh` определял завершение агента только по настоящему событию `{"type":"agent_end"}`, чтобы запуск не зависал во взаимоблокировке и не терял работу.

### Цель по SMART (Goal)
За одну задачу исправить классификацию завершения pi-раннера в `docs/agents/skills/run-subagent/scripts/watch-subagent.sh` (три места: горячий цикл чтения, проверка OUTFILE, подсчёт статистики) на якорную проверку топ-уровневого поля `"type":"agent_end"`; добавить осушение FIFO на время ожидания процесса; покрыть регрессионным интеграционным тестом на существующем каркасе `WatchSubagentScriptTest`.

## 2. Контекст и Границы (Context and Scope)
*   **Где делаем:** `docs/agents/skills/run-subagent/scripts/watch-subagent.sh`; тесты — `tests/Integration/Docs/Agents/Skills/RunSubagent/WatchSubagentScriptTest.php`; документация — `docs/agents/skills/run-subagent/SKILL.md` (если меняется поведение, описанное там).
*   **Уязвимые места (текущее состояние):**
    *   `is_runner_success_event()` (строка ~623): `[[ "$line" == *"agent_end"* ]]` — срабатывает на подстроку в любом месте строки, включая `result.content[].text` события `tool_execution_end`. Основной доказанный путь дедлока.
    *   `outfile_has_success_event()` (строка ~647): `grep -q 'agent_end'` — та же ложная срабатываемость на холодном пути (после закрытия канала).
    *   Подсчёт статистики (строка ~700): `grep -c '"agent_end"'` — завышает счётчик при вхождении `"agent_end"` в тексте результата.
*   **Доказанная механика дедлока:** ложное срабатывание → `wait_agent` → `wait $PID` (syscall `wait4`) без чтения FIFO → pi блокируется на `write()` в заполненный буфер FIFO (зафиксировано: `FIONREAD=64822`, у зависшего pi единственный активный хендл — `Socket fd=1 pendingWrite=1`) → убийство по stall (exit 143, `runner_failed_after_agent_end`).
*   **Формат событий pi:** одна JSON-строка на событие, сериализация начинается с топ-уровневого ключа `"type"` (`{"type":"session"...`, `{"type":"tool_execution_end"...`, `{"type":"agent_end"...}`). Якорная проверка префикса безопасна и не требует fork (важно: в горячем цикле fork запрещён — см. комментарий про pipe-backpressure в самом скрипте).
*   **Ограничение горячего цикла:** проверка должна оставаться на bash-builtin'ах (префиксное сравнение `[[`), без `jq`/`grep` на каждую строку.
*   **Границы (Out of Scope):** не менять протокол codex-ветки (`turn.completed` уже проверяется через `jq` корректно); не менять таймауты и liveness-логику watcher; не трогать PHP-раннер (`AgentRunner`) — у него собственный парсинг JSONL.

## 7. Риски и зависимости
*   Формат сериализации событий pi: если топ-уровневый `"type"` перестанет быть первым ключом, префиксная проверка сломается. Митигация: тест фиксирует формат; при смене формата pi — обновить паттерн.
*   Осушение FIFO фоновым читателем может гоняться с чтением основного цикла — осушение активировать только после решения о завершении (в `wait_agent`), где основной цикл уже не читает.
*   Живой smoke зависит от внешнего провайдера; при недоступности — ограничиться интеграционным тестом и отметить в отчёте.
