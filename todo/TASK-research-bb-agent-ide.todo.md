# TASK-research-bb-agent-ide: Исследовать bb как agentic IDE и control surface над внешними coding agents

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

- В исследовательском треке уже изучены отдельные агенты программирования, оркестраторы и управляющие поверхности, но нет систематизированной оценки [bb](https://getbb.app/).
- По предварительной классификации bb не выполняет программирование собственным агентным циклом: это `agentic IDE / control surface` (агентная среда разработки и управляющая поверхность) над внешними агентами Claude Code, Codex, Cursor, Pi, OpenCode, Grok, omp и Hermes.
- Без отдельного исследования нельзя обоснованно определить, отличаются ли механизмы bb от уже изученных Orca ADE, qm, omnigent и Herdr и применимы ли его подходы к параллельной работе, изоляции Git, расширению и локальному управлению в `task-orchestrator`.

### Варианты или путь решения (Solution Sketch)

- Исследовать bb по официальному сайту, документации и доступным первичным материалам, привязав изменяемые сведения к дате и версии либо commit snapshot (снимку коммита), если они доступны.
- Рассмотреть bb как надстройку над внешними агентами, отдельно от возможностей самих Claude Code, Codex, Cursor, Pi, OpenCode, Grok, omp и Hermes.
- Сопоставить результаты с `task-orchestrator` и ближайшими аналогами текущего трека: Orca ADE, qm, omnigent и Herdr.

### Ожидаемый результат (Expected Result)

- Команда получает проверяемое понимание места bb в таксономии агентных инструментов и отличий от ближайших управляющих поверхностей.
- Для `task-orchestrator` сформирован обоснованный перечень применимых, неприменимых и требующих отдельной проверки паттернов.
- Выводы включены в общий сравнительный трек без преждевременной интеграции bb или создания задач реализации.

## 1. Концепция и Цель (Concept and Goal)

### История (Job Story)

> **Когда** мы оцениваем способы координации нескольких внешних агентов программирования, **я хочу** исследовать bb как агентную среду разработки и управляющую поверхность, **чтобы** понять применимость его потоков, рабочих деревьев Git, расширений, интерфейсов управления и локальной модели к `task-orchestrator`.

### Цель по SMART (Goal)

В рамках отдельной исследовательской итерации изучить bb по воспроизводимым первичным источникам, описать его классификацию, архитектурные границы, потоки работы, модель состояния, Git worktrees (рабочие деревья Git), расширяемость, оркестрацию поставщиков, интерфейсы, локальность, телеметрию и безопасность; затем создать `docs/research/framework-comparisons/bb-comparison.md` и обновить `docs/research/agent-frameworks-summary.md` с проверяемым вердиктом и рекомендациями для `task-orchestrator`.

## 2. Контекст и Границы (Context and Scope)

* **Тип работ:** `research` (исследование) по RACI; в метаданных указан канонический `type: docs`, поскольку текущая схема `todo-md` не поддерживает значение `research`, а результат ограничен документацией.
* **Объект:** bb с сайта [getbb.app](https://getbb.app/) — предварительно `agentic IDE / control surface` над внешними агентами Claude Code, Codex, Cursor, Pi, OpenCode, Grok, omp и Hermes, а не самостоятельный `coding agent` (агент программирования).
* **Где делаем:** `docs/research/framework-comparisons/bb-comparison.md`, `docs/research/agent-frameworks-summary.md`, [EPIC-research-agent-frameworks-comparison](done/EPIC-research-agent-frameworks-comparison.md).
* **Ближайшие аналоги:** [Orca ADE](done/TASK-research-onorca-ade.todo.md), [qm](done/TASK-research-qm.todo.md), [omnigent](done/TASK-research-omnigent.todo.md), [Herdr](done/TASK-research-herdr.todo.md).
* **Предварительный фокус:** threads (потоки работы), Git worktrees, plugins/self-customization (плагины и самонастройка), multi-provider orchestration (оркестрация нескольких поставщиков), CLI/HTTP API, local-first model (локальная модель), telemetry/security (телеметрия и безопасность), применимость паттернов к `task-orchestrator`.
* **Текущее поведение:** сводка содержит результаты по соседним управляющим поверхностям, но не содержит отдельной строки и проверенного вердикта по bb.
* **Границы (Out of Scope):** не выполнять исследование при постановке задачи; не создавать `bb-comparison.md`, не обновлять сводку фактическими выводами, не устанавливать и не запускать bb; не менять код, конфигурацию, цепочки, роли и зависимости проекта; не создавать отдельный research-отчёт Аналитика в `docs/agents/reports/` в рамках постановки.

## 7. Риски и зависимости (Risks and Dependencies)

- Публичная информация о bb может меняться или быть неполной; технические выводы необходимо привязать к дате и воспроизводимому идентификатору, если он доступен.
- Часть поведения может принадлежать подключаемому агенту, а не bb; смешение этих уровней приведёт к неверной классификации.
- Наличие CLI или HTTP API само по себе не подтверждает стабильность, полноту или пригодность контракта для автоматизации.
- Local-first модель не равнозначна отсутствию телеметрии и сетевых зависимостей; эти свойства проверяются независимо.
- Плагины и самонастройка увеличивают поверхность атаки; выводы без документированной модели доверия должны быть ограничены.
- Ближайшие аналоги различаются по уровню абстракции: Orca ADE — среда параллельной ручной оркестрации, qm и omnigent — мета-харнесы/платформы, Herdr — терминальная среда выполнения и управляющая поверхность.
- Текущий файл эпика имеет legacy-имя без суффикса `.todo.md`; `todo-md` не распознаёт его как EPIC-ID. Поэтому связь зафиксирована двусторонними Markdown-ссылками в задаче и плане эпика, а поле `epic` оставлено пустым до отдельной миграции legacy-файла.

- Создан [bb-comparison.md](../docs/research/framework-comparisons/bb-comparison.md) по официальному сайту, документации и исходникам снимка `fc94f46c13b89f54e9c8ba53600352df64b81798` (`bb-app` 0.40.0).

Поэтому итоговая классификация уточнена до `agentic IDE / programmable control surface + optional workflow engine` (агентная среда разработки и программируемая управляющая поверхность с опциональным движком процессов).
- Подтверждены интеграции Claude Code, Codex, Cursor/ACP, Pi, OpenCode, Grok Build, omp и Hermes; функции внешних агентов отделены от функций bb.

- Повторный пересчёт тренда `SKILL.md` по явно зафиксированному критерию дал 28/36: в сводке перечислены ровно 28 учтённых проектов; ранее в перечне были пропущены Claude Code (#11) и omnigent (#33). Таблица 17 уровней содержит ровно 36 уникальных позиций: пропусков и дублей нет; Odysseus (#27) добавлен, GitHub Copilot Cloud Agent приведён к каноническому названию.
- Вердикт: 🟡 заимствовать provider/thread/durable-replay/worktree patterns (паттерны поставщиков, потоков, устойчивого воспроизведения и рабочих деревьев); 🔴 не core dependency (не основная зависимость); 🟢 допустим как optional manual environment (опциональная ручная среда) после отдельной проверки ownership/security (владения и безопасности).
