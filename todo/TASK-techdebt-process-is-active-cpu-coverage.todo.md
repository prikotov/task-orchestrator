# TASK-techdebt-process-is-active-cpu-coverage: Покрытие CPU-ветки process_is_active в watch-subagent.sh

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Liveness-детектор `process_is_active` в `docs/agents/skills/run-subagent/scripts/watch-subagent.sh` засчитывает активность по дельте CPU (`ps -o times`) **или** IO (`/proc/<pid>/io`). Замечание N3 из ревью PR #512: после детерминизации `WatchSubagentScriptTest` через IO-телеметрию CPU-ветка осталась без тест-покрытия — регрессия именно CPU-детекции (например, поломка парсинга `ps times` или сравнения дельты) никакой тест не поймает.

### Варианты или путь решения (Solution Sketch)
- Добавить интеграционный тест (в класс `WatchSubagentScriptTest` или соседний), детерминированно проверяющий CPU-ветку: процесс с гарантированным CPU-прогревом в окне liveness (реальный busy-loop без IO-телеметрии) признаётся `live=active` по CPU-дельте.
- Сложность дизайна: гарантировать ненулевую квантованную CPU-дельту (>0 целых секунд за окно watcher'а) без CPU-голодания — процесс должен успеть набрать ≥1 CPU-сек между замерами; окно/интервалы подобрать детерминированно (например, увеличенный `WATCH_WATCHER_INTERVAL` и «тёплый» busy-loop, стартующий до первого замера).
- Альтернатива для изоляции от окружения: вынести `process_is_active` в тестируемую обёртку с инъекцией источников CPU/IO (решение за исполнителем на этапе проектирования; правка скрипта — только если не решается тестом).

### Ожидаемый результат (Expected Result)
- CPU-ветка `process_is_active` покрыта детерминированным тестом (стабилен под нагрузкой); регрессия CPU-детекции ловится прогоном phpunit.
