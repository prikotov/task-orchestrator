# TASK-feat-brainstorm-participant-prompts: Лимиты ответов, напоминание о tools, структура ответа участников

## 1. Concept and Goal (Концепция и Цель)
### Story (User Story)
> Как фасилитатор brainstorm, я хочу получать от участников лаконичные (≤ 3000 символов), структурированные ответы с проверкой фактов в коде, чтобы дискуссия была сфокусированной и фактологической.

### Goal (Цель по SMART)
Обновить промпт `config/prompts/brainstorm/participant_append.txt`: (1) добавить лимит 3000 символов и 5-7 минут, (2) добавить напоминание о доступности tools для чтения файлов проекта, (3) добавить структурированный формат ответа (Позиция → Аргумент → Контраргумент → Что принимаешь).

## 2. Context and Scope (Контекст и Границы)
*   **Где делаем:** `config/prompts/brainstorm/participant_append.txt` — текущий промпт участника
*   **Текущее поведение:** Промпт содержит 5 правил поведения (защищай позицию, оспаривай, признавай, не избегай, отвечай на challenge). Нет лимитов длины, нет напоминания о tools, нет структуры ответа.
*   **Границы (Out of Scope):**
    *   Не меняем `participant_user.txt` (шаблон с файлами и темой)
    *   Не меняем `brainstorm_system.txt` (общий системный промпт)
    *   Не добавляем программный контроль длины (контроль через промпт — достаточно)

## 3. Requirements (Требования, MoSCoW)
### 🔴 Must Have (Обязательно)
- [ ] В промпте указан лимит: «Ответ — не более 3000 символов. Если нужно больше — ты не сфокусирован на главном аргументе.»
- [ ] В промпте указан лимит времени: «У тебя 5-7 минут на подготовку ответа. Фокусируйся на главном.»
- [ ] В промпте есть напоминание о tools: «Ты имеешь доступ к файлам проекта через tools (read, bash). Если нужны факты из кода — читай файлы. Не угадывай — проверяй.»
- [ ] В промпте задан структурированный формат ответа:
  ```
  ### Моя позиция (1-2 предложения)
  ### Ключевой аргумент (до 500 символов)
  ### Контраргумент оппоненту (до 500 символов, если применимо)
  ### Что я готов принять (1-2 предложения)
  ```
### 🟡 Should Have (Желательно)
- [ ] Структура ответа — рекомендация, а не жёсткий шаблон (участник может отклоняться при необходимости)
### 🟢 Could Have (Опционально)
### ⚫ Won't Have (Не будем делать)
- [ ] Программная обрезка ответа (enforcement через промпт)

## 4. Implementation Plan (План реализации)
*Заполняется исполнителем перед стартом.*
1. [ ] Прочитать текущий `participant_append.txt`
2. [ ] Добавить секцию «Ограничения» с лимитом длины и времени
3. [ ] Добавить секцию «Инструменты» с напоминанием о tools
4. [ ] Добавить секцию «Формат ответа» со структурированным шаблоном
5. [ ] Проверить, что общая длина промпта не превышает разумный предел (< 2000 символов)

## 5. Definition of Done (Критерии приёмки)
- [ ] `participant_append.txt` содержит все 3 дополнения (лимиты, tools, структура)
- [ ] Промпт остаётся читаемым и лаконичным
- [ ] Изменения промпта не ломают существующие тесты (если есть тесты на парсинг промптов)

## 7. Risks and Dependencies (Риски и зависимости)
- Модели могут игнорировать лимит в 3000 символов — это известное ограничение промпт-инструкций. Но даже частичное соблюдение (5000 вместо 18000) — огромный выигрыш.
- Структурированный формат может конфликтовать с экспрессивным стилем некоторых ролей (Локи, Шерлок) — поэтому он рекомендация, а не требование.
