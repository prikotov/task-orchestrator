# TASK-chore-two-track-code-review: Двухтрековое ревью кода: оформление модели (PM4/PM5)

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Этап ревью сейчас — один ревьювер проверяет всё сразу (требования, архитектуру, безопасность, тесты, конвенции): распыление внимания LLM-ревьювера, архитектор не владеет архитектурным ревью, замечания разных типов не разделяются по судьбе.
- Модель двухтрекового ревью (RV-F функциональное + RV-A архитектурное) спроектирована и принята через специализированный цикл PM1–PM3 (раздел 6 RACI): черновик в `var/research-tmp/review-split-model-draft.md`. Требуется оформление принятой модели в нормативные документы проекта.

### Варианты или путь решения (Solution Sketch)
- PM4: технический писатель оформляет принятую модель в артефакты из раздела 2.6 модели (SDLC, RACI, два скилла, четыре файла ролей) + отчёт цикла в `docs/agents/reports/team-lead/`.
- PM5: тимлид сверяет оформление с моделью (сохранность управленческих решений).
- RV: ревьювер бэка проверяет согласованность и связность документов.
- Проверки проекта: изменения только документационные — PHPUnit/Psalm пропускаются по исключению AGENTS.md; `validate-language` обязателен.

### Ожидаемый результат (Expected Result)
- Этап RV в RACI разделён на RV-F (A/R — ревьювер бэка) и RV-A (A/R — архитектор) с гейтингом; SDLC описывает два трека; скиллы содержат шаги 5а/5б; роли обновлены; отчёт цикла зафиксирован. Модель вступает в силу после слияния.
