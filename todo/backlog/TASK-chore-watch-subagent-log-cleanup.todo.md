# TASK-chore-watch-subagent-log-cleanup: Ручная очистка и диагностика архивов watch-subagent

## 1. Concept and Goal (Концепция и Цель)

### Story (User Story)

Как разработчик/оператор, я хочу вручную чистить и инспектировать архив
постмортем-ранов `watch-subagent` (`var/log/watch-subagent/`), чтобы:
(a) освобождать место на внутреннем диске, когда архив разросся;
(б) быстро находить проблемные раны (большие `events.ndjson`, зависания)
для разбора багов — не выгребая 1600+ каталогов руками.

### Goal (Цель по SMART)

- **Конкретный:** CLI-утилита с двумя режимами — `cleanup` (удаление старых
  и/или сверхквоты архивов) и `report`/`diag` (сводка состояния и аномалий).
- **Измеримый:** запускается вручную, не требует cron/таймера.
- **Достижимый:** bash-скрипт или Symfony console-команда поверх
  `var/log/watch-subagent/`.
- **Relevant:** архив полезен для разбора багов (хранить!), но без очистки
  копится бесконечно. На момент создания задачи — **232 МБ / 1627 каталогов**
  за ~месяц, один каталог — до 201 МБ (один зависший ревью).
- **Time-bound:** задача в бэклоге, берётся по мере роста архива.

## 2. Context and Scope (Контекст и Границы)

- `var/log/watch-subagent/<run-id>/` — постмортем-архив одного запуска:
  `events.ndjson` (часто десятки/сотни МБ), `gaps.tsv`, `runner.stderr`,
  `run.log`.
- Создаётся функцией `archive_events()` в
  `docs/agents/skills/run-subagent/scripts/watch-subagent.sh` при
  зависании/ошибке/прерывании. Каталог определяется `WATCH_LOG_DIR`.
- **Никакой ротации нет** — каталог копится бесконечно на внутреннем диске.
- 🚫 **Не цель:** авто-ротация по cron/timer. Архив нужен для разбора багов —
  только ручная очистка по запросу.
- 🚫 **Не цель:** GC общего `/tmp` (там разбирается ОС через
  `systemd-tmpfiles`, отдельная тема — см. PR #291 и отказ от него).

## 3. Requirements (Требования)

### 🔴 Must Have

- **Режим `cleanup`:** удаляет архивы старше N дней (env/флаг, напр. 30) И/ИЛИ
  при превышении квоты M МБ (удалять самые старые LRU, пока не уложимся).
- **Dry-run по умолчанию:** показывает кандидатов на удаление, ничего не
  трогая; реальное удаление — только по явному флагу (`--force`).
- **Режим `report`/`diag`:** суммарный размер, число каталогов, топ-N по
  размеру, топ по возрасту, аномалии (`events.ndjson` больше порога = кандидат
  в зависшие раны — самый ценный сигнал для разбора багов).

### 🟡 Should Have

- Фильтры: `--role=`, `--runner=`, `--since=` (по префиксу имени каталога).
- Экспорт сводки в JSON (`--format=json`) для скриптов/дашборда.

### 🟢 Nice to Have

- Цветной человекочитаемый вывод в `report`.
- Подключение как утилита скилла `run-subagent` (рядом с
  `watch-subagent.sh`).

## 4. Implementation Plan

1. Выбрать носитель: bash-скрипт (`bin/watch-subagent-log`) для консистентности
   с самим `watch-subagent.sh`, **либо** Symfony console-команда
   (`apps/console .../Command/...`) для консистентности с проектом. На старте
   проще bash.
2. Реализовать `cleanup` с dry-run по умолчанию и `--force`; критерии —
   возраст (`--older-than-days`) и квота (`--max-size-mb`, LRU).
3. Реализовать `report`/`diag`: размер/счётчики/топ/аномалии.
4. Тест: integration-тест на фикстурах — dry-run не удаляет, `--force` удаляет
   строго по возрасту/квоте, свежие архивы защищены.
5. Документация: `docs/agents/skills/run-subagent/SKILL.md`,
   `docs/guide/troubleshooting.md`.

## 5. Definition of Done

- Утилита работает в режимах `cleanup` и `report`.
- `cleanup` — dry-run по умолчанию, удаление только по `--force`.
- Тесты покрывают cleanup (возраст, квота, защита свежих) и report.
- Документация обновлена, путь вызова описан.

## 6. Verification

- `report` на реальном `var/log/watch-subagent/` — показать ~232 МБ /
  1627 каталогов (на момент создания задачи).
- `cleanup` dry-run — перечислить кандидатов без удаления.
- `cleanup --force --older-than-days=30` — освобождает место, свежие
  каталоги (текущие дни) остаются.

## 7. Risks

- **Случайное удаление нужного архива** → mit: dry-run по умолчанию, явный
  `--force`, верхняя граница возраста (не трогать моложе N дней даже при
  превышении квоты — по решению оператора).
- **Путь к архиву отличается** (`WATCH_LOG_DIR` env) → читать путь из
  env/скрипта, не хардкодить.
