# TASK-docs-done-before-approval-sync: Синхронизация потребителя: done до запроса апрува (upstream v0.3.2 / v0.0.12)

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Регламент требовал переводить задачу в `done` коммитом в ветку PR ПОСЛЕ апрува владельца. Защита ветки `require_last_push_approval` при любом новом пуше снимает апрув — порядок «апрув → done-коммит → merge» заставлял владельца ставить одобрение повторно в каждом PR (4 лишних approve на 3 PR: #362, #363, #364).
- Канон исправлен в upstream: `prikotov/git-workflow` v0.3.2 (PR #8: раздел «Подготовка PR») и `prikotov/todo-md` v0.0.12 (PR #29: модель `review`/`done`). Проект-потребитель остался на старых версиях и старых формулировках.

### Варианты или путь решения (Solution Sketch)
- `composer update prikotov/git-workflow prikotov/todo-md` → перегенерация распределяемых документов (`git-workflow-init --force`, `todo-md init --force`).
- Синхронизировать собственные нормативы потребителя с новым каноном: корневой `AGENTS.md`, SKILL `epic-via-subagents` (перенос подготовки PR до запроса ревью), реестр ретро (`RETRO-ROADMAP.md`: запись → `resolved`).
- Восстановить проектные кастомизации, стираемые init: списки ролей/агентов в `.todo-md.php`, два ретро-правила в корневом `AGENTS.md` (локальный `todo/AGENTS.md` — генерируемый, больше их не содержит).

### Ожидаемый результат (Expected Result)
- Все нормативы проекта предписывают: после зелёного CI и до запроса апрува — done + push; после апрува в PR-ветку не пушится ничего, только merge.
- grep по репо не находит предписаний «после апрува переведи в done / запушь» (кроме исторических записей ретро-архива и done-задач).
- Запись реестра ретро о снятии апрува done-коммитом переведена в `resolved` со ссылками на upstream-решения и этот PR.
