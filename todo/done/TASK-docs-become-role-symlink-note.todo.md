# TASK-docs-become-role-symlink-note: Добавить в SKILL.md become-role примечание о симлинке .agents/skills/become-role (ловушка find без -L)

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

В source/Composer-установках task-orchestrator каталог `.agents/skills/become-role` — **симлинк** на `docs/agents/skills/become-role/` (так делает `agent:init`, чтобы pi/codex видели скилл нативно; в PHAR-установке — реальная копия). Команда `find <путь-через-симлинк> -type f` **без `-L`** не заходит внутрь симлинка и молча возвращает пустой список с кодом успеха — «каталог пуст», хотя файлы есть.

Реальный случай (2026-11-24): сабагент в сбойном запуске проверил каталог скилла ровно такой командой, получил пустоту, начал перепроверять — и модель без рассуждений ушла в цикл из ~590 повторов (запуск снят по таймауту, задача не сдвинулась). `SKILL.md` скилла про этот эффект не говорит ничего — агент, желающий проверить содержимое каталога, получает обманчивый результат без объяснения.

### Варианты или путь решения (Solution Sketch)

Один вариант: два-три предложения в `SKILL.md` (и зеркало в `README.md`) — «`.agents/skills/become-role` может быть симлинком (source/Composer-установка; в PHAR — копия); для проверки содержимого каталога используй `find -L` или реальный путь `docs/agents/skills/become-role/`». Файлы и скрипт не меняются.

### Ожидаемый результат (Expected Result)

Агент, читающий `SKILL.md` и желающий проверить содержимое каталога скилла, получает явное объяснение структуры установки и рабочую команду проверки — пустых «ложных тревог» больше нет. Проверки (`make md-links`, `validate-language`, `todo-md validate`) зелёные.
