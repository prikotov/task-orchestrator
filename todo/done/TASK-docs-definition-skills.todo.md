# TASK-docs-definition-skills: Навыки постановки и цикл проектирования процессов команды

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Постановки задач и эпиков в принимающих проектах готовились вручную, без единого протокола: постановки выходили разнородными, состав участников подбирался «на глаз».
- Как команда проектирует и согласовывает изменения собственных регламентов, матрицы ответственности и оркестрационных навыков — нигде не было закреплено: такие изменения проводились как обычная документация, без явного цикла согласования и принятия модели.
- Это мешало тимлиду (нет закреплённого права и порядка личного проектирования процессов) и техническим писателям (нет правила «вход оформления — только принятая модель»), а принимающие проекты не получали переносимого способа готовить постановки по своей матрице RACI.

### Варианты или путь решения (Solution Sketch)
- Переносимый набор навыков постановки: `task-definition` (одиночная задача), `epic-definition` (постановка эпика), `epic-decomposition` (декомпозиция эпика) с общим протоколом подготовки постановок.
- Специализированный цикл «Проектирование процессов взаимодействия команды» (`PM1`–`PM5`) в матрице RACI: модель → проверка → принятие → оформление → сверка; правила цикла применяются к изменениям регламентов, навыков и распределения ответственности.

### Ожидаемый результат (Expected Result)
- В принимающих проектах постановки задач и эпиков готовятся навыками по строкам матрицы RACI принимающего проекта: контекст → черновик → консультации → проверка → принятие.
- Изменения регламентов, матрицы ответственности и оркестрационных навыков проходят цикл `PM1`–`PM5` до публикации: модель проектирует и принимает тимлид, оформление выполняет технический писатель, готовность подтверждается сверкой.
- Роли тимлида и технических писателей, а также README (ru/en/zh) описывают новое разделение труда; статическая сверка модели зафиксирована отчётом.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> **Как** Тимлид, **я хочу** переносимые навыки постановки задач и эпиков и закреплённый цикл проектирования процессов взаимодействия команды, **чтобы** постановки в принимающих проектах готовились однородно по матрице RACI, а изменения регламентов и навыков согласовывались явно до публикации.

### Цель по SMART (Goal)
- **S:** Оформить три навыка постановки (`task-definition`, `epic-definition`, `epic-decomposition`) с общим протоколом, специализированный цикл `PM1`–`PM5` в [матрице RACI](../../docs/agents/raci-matrix.md), обновления ролей тимлида и технических писателей, README (ru/en/zh) и отчёт статической сверки.
- **M:** `todo-md validate` и `make md-links` зелёные; `make validate-roles` и `make validate-language` зелёные; статическая сверка с внешней матрицей TasK зафиксирована отчётом; остались CI в PR и создание PR.
- **A:** Только документация в существующих каталогах (`docs/agents/`), без кода и конфигураций; опирается на справочники и шаблоны пакета todo-md.
- **R:** Переносимая продуктовая ценность для принимающих проектов (навыки постановки) и процессная основа команды (цикл проектирования процессов).
- **T:** Ветка `task/definition-skills`; работа выполнена и оформляется к PR в текущей итерации.
