# TASK-docs-rv-report-in-prompt: Явное требование файла отчёта в промпте полного RV конвейера

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

Полные ревью (RV) Ревьювера Бэка Пуаро не оставляют файлового артефакта: вердикты живут только в журнале сессии и пересказах. В роли Пуаро скилл `agent-report` подключён с PR #496 (мягкая формулировка «по умолчанию сохраняй файлом»), но поведение не изменилось — правило в роли не сработало, потому что точка исполнения находится у запускающего: промпт RV в конвейере (`task-via-subagents/SKILL.md`, Шаг 5) требование файла не содержит, а запуски идут с `output=text`. Это третье упоминание в реестре `RETRO-ROADMAP.md` («RV-F ревью не оставляет отчётного артефакта») — порог эскалации достигнут. В серии PR #500–#504: CHANGE REQUEST stall-задачи и оба APPROVED — без файлов; отчёт #500 появился только благодаря ручной архивации тимлида (коммит `8cbb5314`).

### Варианты или путь решения (Solution Sketch)

В шаблон промпта ревьювера на Шаге 5 `task-via-subagents/SKILL.md` добавить явное требование: полный RV сохраняет отчёт файлом в `docs/agents/reports/code-reviewer-backend/ с именем файла ГГГГ-ММ-ДД_ЧЧ-ММ-slug-review.md`; короткий вердикт в чате допустим только для верификационных проходов. Требование идёт от запускающего (промпт), а не только от роли.

### Ожидаемый результат (Expected Result)

Каждый полный RV конвейера оставляет файл отчёта в `docs/agents/reports/code-reviewer-backend/`; вердикты верификационных проходов остаются короткими. Критерий: пункт в шаблоне промпта Шага 5 `task-via-subagents/SKILL.md`, doc-проверки зелёные; при следующем полном RV файл создаётся исполнителем сам.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)

> Как тимлид, запускающий конвейер задачи, я хочу, чтобы полный RV сохранял отчёт файлом без ручной архивации, чтобы артефакты ревью были первоисточниками, а не пересказами в журнале сессии.

### Цель по SMART (Goal)

Шаблон промпта RV на Шаге 5 `task-via-subagents/SKILL.md` дополнен явным требованием файла отчёта с путём и правилом короткого вердикта для верификаций; критерий: пункт в файле, doc-проверки зелёные, следующий полный RV серии оставляет файл без ручной архивации.

## 2. Контекст и Границы (Context and Scope)

*   **Где делаем:** `docs/agents/skills/task-via-subagents/SKILL.md` — Шаг 5 «Ревью», шаблон промпта ревьювера.
*   **Текущее поведение:** шаблон промпта содержит проверки и формат вердикта, но не требует файла отчёта; запуски RV идут с `output=text`.
*   **Прецеденты:** роль Пуаро (PR #496) — мягкая формулировка «по умолчанию файлом»; структура существующих отчётов в `docs/agents/reports/code-reviewer-backend/` (например, `2026-11-24_17-46_docs-full-option-names-skills-review.md`).
