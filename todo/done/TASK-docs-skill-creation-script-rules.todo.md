# TASK-docs-skill-creation-script-rules: Правила скриптов и путей в SKILL-CREATION.md

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
Агенты при сбоях запуска скриптов навыков (skill) повторно предлагают нестандартное «исправление»: заменить относительную команду `scripts/foo.sh` в `SKILL.md` на путь от корня проекта или абсолютный. Это нарушает стандарт Agent Skills (навык обязан быть переносимым) и уже отклонялось владельцем несколько раз. Правила создания навыков (`SKILL-CREATION.md`) ссылаются на стандарт, но не содержат жёсткого раздела про скрипты и пути — якорить правило негде.

### Варианты или путь решения (Solution Sketch)
Добавить в `SKILL-CREATION.md` обязательный раздел «Скрипты и пути»: форма команды только стандартная относительная; резолв пути — контракт раннера (pi/Claude Code/Codex вставляют правило в системный промпт и отдают абсолютный `<location>`); комментарий-якорь в code block как подстраховка; скрипты — самонастраивающиеся (self-locating), не зависят от cwd; тесты покрывают оба контекста запуска. Зафиксировать то же в записи реестра ретро.

### Ожидаемый результат (Expected Result)
Правила создания навыков содержат проверяемые правила скриптов и путей; агенты (и ревьюверы) ссылаются на них вместо придумывания обходных форм; при разборе повторных инцидентов `exit 127` / потери пути решение сверяется с разделом, а не с примерами соседнего кода.

## 1. Концепция и Цель (Concept and Goal)

### История (Job Story)
> Когда агент или ревьювер встречает сбой запуска скрипта навыка и хочет предложить заменить форму команды в `SKILL.md`, я хочу, чтобы в `SKILL-CREATION.md` был обязательный раздел с правилами, чтобы нестандартные предложения отсекались документом, а не только владельцем.

### Цель по SMART (Goal)
Добавить в `docs/agents/skills/SKILL-CREATION.md` раздел «Скрипты и пути» из шести проверяемых правил (форма команды, контракт резолва, комментарий-якорь, самонастройка скрипта, покрытие тестами обоих контекстов, разделение форм SKILL.md vs документы хоста), убрать случайный дубль раздела «Стандарты и источники» и синхронизировать связанную запись в `docs/agents/team-retro/RETRO-ROADMAP.md`.

## 2. Контекст и Границы (Context and Scope)

*   **Где делаем:** `docs/agents/skills/SKILL-CREATION.md` (новый раздел + удаление дубля), `docs/agents/team-retro/RETRO-ROADMAP.md` (обновление решения по записи про `watch-subagent.sh` → `exit 127`).
*   **Текущее поведение:** правила создания навыков не описывают контракты скриптов и путей; раздел «Стандарты и источники» продублирован дважды; в реестре ретро кандидат по `watch-subagent.sh` не связан с общим правилом.
*   **Факты для формулировок (проверены по исходникам):**
    *   pi вставляет в системный промпт: «When a skill file references a relative path, resolve it against the skill directory (parent of SKILL.md / dirname of the path) and use that absolute path in tool commands» — плюс абсолютный `<location>` каждого навыка (`dist/core/skills.js`, `@earendil-works/pi-agent-core/dist/harness/system-prompt.js`).
    *   Стандарт: [Agent Skills — Using scripts](https://agentskills.io/skill-creation/using-scripts) — пути к скриптам относительно каталога навыка.
    *   Образец комментария-якоря: встроенные навыки codex (`plugin-creator`: «Run from the skill root»); наш аналог уже в `become-role/SKILL.md` (PR #362).
    *   Самонастройка скрипта: `BASH_SOURCE` + логический путь (`pwd -L`) для восстановления host-root — контракт `become-role.sh` (PR #371, v0.5.1).
*   **Границы (Out of Scope):** не меняем существующие SKILL.md навыков и код скриптов; не меняем форму команд в `README.md`/`cli.md`/`troubleshooting.md`; обновление host-проектов (stocks2 → v0.5.1) — вне задачи, отдельное действие владельца; реестр ретро не реструктурируем — обновляем только связанную запись.
