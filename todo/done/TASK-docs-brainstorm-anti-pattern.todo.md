# TASK-docs-brainstorm-anti-pattern: Добавить анти-паттерн симуляции brainstorm в SKILL.md

## 1. Concept and Goal (Концепция и Цель)
### Story (User Story)
> Когда AI-агент в роли Тимлида получает запрос на brainstorm, я хочу, чтобы в SKILL.md был явный запрет на симуляцию, чтобы агент не выдумывал позиции участников у себя в голове, а запускал реальную сессию через CLI.

### Goal (Цель по SMART)
Добавить в `docs/agents/skills/brainstorm/SKILL.md` раздел «Анти-паттерны» с жёстким правилом: brainstorm **всегда** запускается через CLI (`php bin/console app:agent:orchestrate "..." --chain=brainstorm`), симуляция позиций участников в голове агента запрещена и считается нарушением роли.

## 2. Context and Scope (Контекст и Границы)
*   **Где делаем:** `docs/agents/skills/brainstorm/SKILL.md`
*   **Текущее поведение:** SKILL.md описывает как правильно проводить brainstorm через CLI, но не содержит явного запрета на симуляцию. Агент может «забыть» про CLI и выдумать результат.
*   **Границы (Out of Scope):** Не обновляем `docs/agents/roles/team/team_lead_alex.ru.md` — пользователь явно исключил это.

## 3. Requirements (Требования, MoSCoW)
### 🔴 Must Have (Обязательно)
- [ ] В SKILL.md добавлен раздел «Анти-паттерны» (перед или после раздела «Результат»)
- [ ] Раздел содержит правило: brainstorm всегда запускается через CLI, симуляция запрещена
- [ ] Раздел содержит пример того, что считается нарушением (выдумывание позиций участников, аргументов и решений без реального запуска CLI)
- [ ] Формулировки на русском языке, в стиле остального документа

### 🟡 Should Have (Желательно)
- [ ] Краткое обоснование: почему симуляция неприемлема (нет реального конструктивного конфликта, один perspective вместо нескольких, результат не проверяем через протокол сессии)

### 🟢 Could Have (Опционально)

### ⚫ Won't Have (Не будем делать)

- [ ] Обновление других файлов ролей
