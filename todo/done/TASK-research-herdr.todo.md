# TASK-research-herdr: Исследовать Herdr v0.8.0 как постоянную терминальную среду выполнения для агентов программирования

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

- В `task-orchestrator` есть декларативные YAML-цепочки, роли, повторные попытки с задержкой, автоматический выключатель, ворота качества, бюджет выполнения, `fix_iterations` (итерации доработки), условные цепочки и журнал JSONL.
- Для запуска подчинённых агентов используется `run-subagent`: он запускает Pi или Codex как отдельный процесс, читает JSONL-события, контролирует мягкий, жёсткий и простойный таймауты, сохраняет диагностические журналы.
- [Herdr](https://herdr.dev/) решает другую часть задачи. Это постоянный фоновый сервер и терминальный мультиплексор для внешних агентов программирования. Он сохраняет реальные терминалы, определяет состояния агентов, позволяет одному агенту запускать и опрашивать другого, управляет рабочими деревьями Git и предоставляет общий интерфейс через командную строку и локальный сокет.
- Нужно определить, какие механизмы Herdr дополняют нашу оркестрацию, а какие нельзя переносить: Herdr не является движком цепочек, не вызывает LLM напрямую и не предоставляет контракт результата, сравнимый с JSONL-выводом наших исполнителей.

### Варианты или путь решения (Solution Sketch)

- Зафиксировать исследование по воспроизводимому выпуску `v0.8.0`, commit `346411fa21afd297f5ed3b3fa56f9e3fbf7654b7`.
- Изучить README, release notes (примечания выпуска), `SKILL.md` (файл навыка), документацию автоматизации, модель состояния сеанса, локальный сокет и ключевые исходники.
- Разделить три поверхности Herdr: топологию `workspace/tab/pane` (рабочая область/вкладка/панель), сырой терминал и семантическое управление распознанным агентом.
- Сравнить Herdr с `task-orchestrator`, `run-subagent`, SwarmForge, Orca ADE и bx-dev. `qm` и `omnigent` отметить как соседние, но ещё не завершённые исследования.
- Оформить отдельный сравнительный отчёт, добавить Herdr как запись #34 и обновить эпик стадией `1m`.

### Ожидаемый результат (Expected Result)

- Создан `docs/research/framework-comparisons/herdr-comparison.md`.
- Herdr классифицирован как `terminal agent runtime / control surface` (терминальная среда выполнения и управляющая поверхность для агентов), а не как агент программирования или движок цепочек.
- Зафиксирован вердикт: 🟡 заимствовать отдельные паттерны; 🔴 не использовать как основную зависимость исполнения; 🟢 допустим отдельный эксперимент как вспомогательная среда ручной работы.
- В сводке есть строка #34; счётчик показывает 32 завершённых исследования из 34 запланированных, потому что #32 (`qm`) и #33 (`omnigent`) ещё ожидают выполнения.

Когда мы развиваем запуск и координацию подчинённых агентов, я хочу изучить Herdr v0.8.0 как постоянную терминальную среду выполнения над Claude Code, Codex, Pi, OpenCode и другими внешними агентами, чтобы понять применимость его событийной модели состояния, безопасной адресации, рабочих деревьев Git, восстановления сеансов и согласованного командного интерфейса к `task-orchestrator`.

Исследовать Herdr `v0.8.0` по зафиксированному commit, описать модель оркестрации, управление состоянием, обработку ошибок, расширяемость, безопасность и применимость. ## 2. Context and Scope (Контекст и границы)

* **Объект:** `herdrdev/herdr` `v0.8.0`, Rust 2021, Apache-2.0, фоновый сервер + клиенты + реальные PTY-терминалы + локальный сокет.
* **Где делаем:** `docs/research/framework-comparisons/herdr-comparison.md`, `docs/research/agent-frameworks-summary.md`, `todo/done/EPIC-research-agent-frameworks-comparison.md`, `docs/agents/reports/system-analyst/`.
* **Текущее поведение:** `task-orchestrator` управляет конечными процессами Pi/Codex и разбирает их JSONL-события. Интерактивные терминальные сеансы не являются его постоянным состоянием.
* **Границы:** только исследование и документация. Не устанавливать Herdr, не запускать его сервер, не добавлять новый исполнитель, зависимость Composer или системный пакет, не менять код и конфигурацию приложения.

## 7. Risks and Dependencies (Риски и зависимости)

- Показатели GitHub изменяются. В отчёте указывается дата измерения, а технические выводы привязаны к commit.
- Распознавание состояния по экрану эвристическое. Неизвестный интерфейс согласования может быть классифицирован как `idle`; `unknown` не означает успех.
- `agent prompt --wait` ждёт изменение состояния текущего агента, а не подтверждённый результат конкретного задания. Уже работающий агент может завершить предыдущий ход и удовлетворить ожидание.
- Обычные ожидания без `--timeout` могут быть бесконечными; потребитель обязан задавать предел.
- Плагины запускаются как обычный код пользователя и не изолируются Herdr.
- #32 (`qm`) и #33 (`omnigent`) зарезервированы, но их исследования не завершены. Сводка временно содержит 32 завершённых результата из 34 запланированных.
