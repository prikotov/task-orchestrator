# TASK-chore-merge-release-0-2-back: Синхронизировать историю релизов 0.2 с main

## 0. Простое описание (Human Brief)
### Проблема простыми словами (Problem)
Ветка `main` не содержит историю завершённых релизов `v0.2.0`–`v0.2.3`: отсутствуют записи `CHANGELOG.md`, release plans (планы релизов) и задачи подготовки. Следующий релиз из `main` теряет проверяемый состав предыдущих выпусков.

### Варианты или путь решения (Solution Sketch)
Выполнить merge-back (обратное слияние) `release/0.2` в отдельной ветке от `main`. При конфликте сохранять более новое поведение `main`, а релизные артефакты переносить полностью.

### Ожидаемый результат (Expected Result)
`main` содержит релизную историю 0.2 и становится единственной корректной базой для следующего релиза.

### История (Job Story)
> **Job Story:** Когда готовится новый релиз, я хочу брать его из `main`, содержащего историю предыдущих релизов, чтобы состав и версия были прослеживаемыми.

В одном Pull Request (запросе на слияние) перенести историю `release/0.2` в `main`, проверить сохранность актуального кода и пройти `make check`.
