# TASK-fix-v0-2-0-runtime-platform-contract: Зафиксировать единый runtime platform contract для v0.2.0

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

Проект обещает поддержку `PHP >= 8.4`, хотя часть установленных компонентов Symfony 8 требует
`PHP >= 8.4.1`. Кроме того, код напрямую использует `symfony/filesystem` и `ext-openssl`, а
`box.json.dist` задаёт GZ-сжатие PHAR, требующее `ext-zlib`, но корневой `composer.json` не объявляет
их прямыми обязательными зависимостями. В результате опубликованный контракт расходится с
фактическими требованиями: установка или запуск могут завершиться ошибкой только на машине
пользователя либо при сборке PHAR (исполняемого PHP-архива).

### Варианты или путь решения (Solution Sketch)

**Decision (принятое решение):** единый минимальный контракт для исходной установки и PHAR:
`PHP >= 8.4.1`, обязательные
`ext-openssl` и `ext-zlib`, прямая зависимость `symfony/filesystem:^8.0` и включённая проверка
платформы Composer (`config.platform-check: true`). `ext-zlib` обязателен, поскольку
`box.json.dist` задаёт GZ-сжатие исполняемого PHAR. Нижняя граница проверяется в окружении,
воспроизводящем production-установку без development-зависимостей.

### Ожидаемый результат (Expected Result)

Composer-метаданные, lock-файл, CI (непрерывная интеграция), PHAR-проверки и действующая
пользовательская документация описывают и проверяют один и тот же минимальный runtime-контракт.
Несовместимое окружение отклоняется до выполнения прикладного кода.

## 1. Concept and Goal (Концепция и Цель)

### Story (Job Story)

> Когда я устанавливаю или запускаю релиз `v0.2.0`, я хочу получить точный и автоматически
> проверяемый список минимальных требований платформы, чтобы несовместимость обнаруживалась при
> установке или старте, а не в середине выполнения команды.

### Goal (Цель по SMART)

До выпуска `v0.2.0` привести Composer-контракт, CI, PHAR-сборку и актуальную документацию к
минимуму `PHP >= 8.4.1`; явно объявить `ext-openssl`, `ext-zlib` и `symfony/filesystem:^8.0`;
обновить `composer.lock`; доказать production-like проверкой (проверкой в окружении, близком к
боевому), что установка без development-зависимостей и собранный PHAR работают на точной нижней
границе.

## 2. Context and Scope (Контекст и Границы)

* **Где делаем:**
  - `composer.json` и `composer.lock` — единый контракт платформы и прямых зависимостей;
  - `.github/workflows/ci.yml` и при необходимости `.github/workflows/release-phar.yml` —
    проверка на точной версии `PHP 8.4.1`, а не на плавающей `8.4`;
  - `bin/phar-smoke`, `Makefile`, `box.json.dist` — только если это необходимо для
    production-like проверки существующей PHAR-сборки;
  - действующие документы с обещанием минимальной версии PHP: `README.md`, `README.en.md`,
    `README.zh.md`, `docs/agents/skills/task-orchestrator/README.md`,
    `docs/guide/extension.md` и другие найденные актуальные руководства.
* **Текущее поведение:**
  - корневой контракт содержит `php: >=8.4`;
  - `ext-openssl` не указан в `require`, хотя нужен модулю GitIdentity;
  - `ext-zlib` не указан в `require`, хотя `box.json.dist` использует GZ-сжатие PHAR;
  - `symfony/filesystem` используется исходным кодом напрямую, но приходит транзитивно;
  - `config.platform-check` явно не включён;
  - CI использует плавающую версию `8.4`, поэтому не доказывает работу на `8.4.1`;
  - пользовательские документы обещают более широкую совместимость, включая `8.4.0`.
* **Границы (Out of Scope):**
  - не исправлять работу `agent:init` внутри PHAR — это отдельная задача выпуска `v0.2.0`;
  - не добавлять отсутствующие release-targets (релизные цели) `Makefile` и не менять общий
    release workflow (процесс выпуска) — это отдельная задача;
  - не обновлять Symfony и остальные пакеты без необходимости для согласования lock-файла;
  - не менять бизнес-логику, публичные CLI-контракты и архитектуру модулей;
  - не переписывать исторические отчёты, исследования и ретроспективы, если упоминание `PHP 8.4`
    описывает исторический контекст, а не действующее обещание совместимости.

## 6. Verification (Самопроверка)

```bash
composer validate --strict
composer install --no-dev --no-interaction --prefer-dist --optimize-autoloader
# Проверка должна явно подтвердить обязательные ext-openssl и ext-zlib.
composer check-platform-reqs --no-dev
make phar-smoke

# После восстановления development-зависимостей.
composer install --no-interaction --prefer-dist
vendor/bin/phpunit
vendor/bin/psalm
make check

# Аудит обещаний совместимости; каждое найденное активное упоминание должно быть
# обновлено до 8.4.1 либо обоснованно признано описанием стека/исторического контекста.
grep -RIn --exclude-dir=vendor --exclude-dir=.git \
  -E 'PHP *>= *8\\.4([^.]|$)|PHP 8\\.4\\+' README*.md docs

# Аудит действующих системных требований на обязательное расширение Zlib.
grep -n 'ext-zlib' README.md README.en.md README.zh.md \
  docs/agents/skills/task-orchestrator/README.md docs/guide/extension.md
```

Production-like команды должны быть выполнены именно на `PHP 8.4.1`; локальный прогон на более
новой patch-версии (исправляющей версии) не заменяет CI-доказательство нижней границы.

## 7. Risks and Dependencies (Риски и зависимости)

- **Release blocker (блокер выпуска):** до выполнения задачи `v0.2.0` нельзя публиковать, поскольку
  заявленная совместимость шире фактической.
- **Риск скрытого обновления:** изменение корневых требований может обновить транзитивные пакеты в
  `composer.lock`. Снижение риска: целевое обновление lock-файла и обязательный ручной аудит diff.
- **Риск ложнозелёной проверки:** `php-version: '8.4'` устанавливает актуальную patch-версию и не
  проверяет нижнюю границу. Снижение риска: явный `8.4.1` в проверке до релиза.
- **Риск расхождения каналов поставки:** Composer-установка может пройти, а PHAR — нет. Снижение
  риска: одна версия PHP и production-like набор для обоих каналов.
- **Риск отсутствующего Zlib:** `box.json.dist` использует GZ-сжатие, поэтому сборка или запуск
  PHAR без `ext-zlib` не соответствуют принятому контракту. Снижение риска: обязательный
  `ext-zlib: *`, `composer check-platform-reqs --no-dev` и PHAR smoke в совместимом окружении.
- **Риск несовместимого окружения пользователя:** объявление `ext-openssl` начнёт корректно
  отклонять установки без расширения. Это намеренный fail-fast (ранний отказ), а не регрессия.
- **Зависимости:** внешних задач для начала нет; завершение обязательно до финальной подготовки
  и публикации `v0.2.0`.
