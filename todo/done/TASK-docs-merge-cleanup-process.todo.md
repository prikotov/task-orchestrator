# TASK-docs-merge-cleanup-process: Синхронизировать правила очистки веток после слияния

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

Правила удаления ветки в `origin` после слияния PR противоречат друг другу в двух документах. AGENTS.md требует «отдельное явное подтверждение пользователя» на удаление remote-ветки, а `docs/git-workflow/pull-request.md` («Удали рабочую ветку локально и в `origin`») и скилл `task-via-subagents` Шаг 7 (`gh pr merge --squash --delete-branch`) выполняют очистку как штатный шаг слияния. Агент, следующий строгому правилу, останавливается и задаёт лишний вопрос владельцу; владелец теряет время (инцидент после PR #357, 2026-08-20).

### Варианты или путь решения (Solution Sketch)

Решение владельца зафиксировано: **очистка после merge — часть процесса, не вопрос**. Привести AGENTS.md в соответствие с уже существующим процессом: удаление ветки слитого PR (локально и в `origin`) — штатный шаг слияния, покрываемый подтверждением самого merge. Отдельное подтверждение сохранить для закрытия PR без слияния и принудительной отправки (force push). Проверить согласованность всех упоминаний поиском по ключевым словам.

### Ожидаемый результат (Expected Result)

Единое правило без противоречий во всех документах: агент после явно подтверждённого merge выполняет полную очистку (локальная ветка, remote-ветка) без дополнительных вопросов; владелец не получает лишних запросов на рутинную операцию.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story или Job Story)

> **Job Story:** Когда PR слит по моему явному подтверждению, я хочу, чтобы агент завершал цикл полной очисткой веток (локально и в `origin`) как штатным шагом процесса, чтобы не отвечать на лишний рутинный вопрос и не копить мусорные ветки.

### Цель по SMART (Goal)

К концу задачи (1 рабочая сессия): во всех документах проекта (`AGENTS.md`, `docs/git-workflow/pull-request.md`, `docs/agents/skills/task-via-subagents/SKILL.md` и др. по поиску) описано единое правило: удаление ветки слитого PR локально и в `origin` — стандартный шаг слияния, не требующий отдельного подтверждения; поиск по ключевым словам (`удали`, `удаление`, `delete-branch`, `origin`) не находит противоречащих формулировок.

    - `AGENTS.md` → «Что запрещено»: «Закрытие PR, удаление remote-ветки и принудительная отправка ветки — только после отдельного явного согласия пользователя.»
    - `docs/git-workflow/pull-request.md` → «После слияние»: «Удали рабочую ветку локально и в `origin`» (строка ~107).

*   **Границы (Out of Scope):**
    - Не меняем: требование явного подтверждения merge (`gh pr merge` без слова владельца — запрещено всегда).

    - Не трогаем: код, конфигурации, тесты.
    - Удаление ветки `main`/`release/*` и чужих незалитых веток — вне правила; речь только о ветке слитого PR.
