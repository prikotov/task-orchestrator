# TASK-docs-stall-default-alignment: Синхронизировать раздел Stall-timeout epic-via-subagents с фактическим дефолтом скрипта (360 сек)

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

Раздел «Stall-timeout» в `docs/agents/skills/epic-via-subagents/SKILL.md` описывает дефолт, которого у скрипта нет: в тексте «По умолчанию 120 сек», а фактический дефолт `watch-subagent.sh` — **360 сек** (`STALL_TIMEOUT=360`, строка 91) и в таблице параметров `run-subagent/README.md` — «360 для всех раннеров». Под неверный дефолт построен весь абзац («Этого достаточно для реализации (C0–C3), но недостаточно для ревью») и таблица «Тип задачи → stall» (120/180/300). Агент или человек, читая раздел, получает значения, расходящиеся с реальным поведением скрипта.

Замечание внесено Ревьювером Бэка Пуаро в ревью PR #500 (2026-11-24) как неблокирующее предсуществующее расхождение.

### Варианты или путь решения (Solution Sketch)

Один вариант: сверить раздел с фактическим поведением скрипта и актуальными таблицами таймаутов (после PR #498), затем переписать текст и таблицу раздела так, чтобы все числа соответствовали реальности. Скрипт НЕ меняется.

### Ожидаемый результат (Expected Result)

Читатель раздела «Stall-timeout» видит фактический дефолт (360 сек) и согласованные с ним рекомендации; ни одно число раздела не противоречит `watch-subagent.sh` и `run-subagent/README.md`. Проверки (`make md-links`, `validate-language`, `todo-md validate`) зелёные.
