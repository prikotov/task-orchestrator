## 1. Механика перевода VO (properties → private + геттеры)

Проверены все 26 VO по полному диффу (`src/Module/*/Domain/ValueObject/*.php`, +1086/−175) и программной сверкой с HEAD:

- **Конструкторы идентичны HEAD**: порядок параметров, типы, значения по умолчанию не изменены (сверка нормализованного списка параметров `public`→`private` по каждому из 26 файлов — расхождений нет). Именованные аргументы (named arguments) в местах создания не затронуты.
- **Promoted-свойства**: все `public` → `private`, классы остались `final readonly`. Публичных свойств в 26 VO не осталось (программный контроль + PHPCS).
- **Геттеры**: у каждого приватного свойства есть геттер; все геттеры тривиальны (`return $this->prop;`), без побочных эффектов. Полнота покрытия свойств геттерами проверена программно — пропусков нет.
- **Bool-нейминг**: все bool-геттеры — `isXxx()`/`hasXxx()` по конвенции `docs/conventions/core-patterns/value-object.md`. Программная проверка — нарушений нет.
- **Сеттеры/with-методы**: не добавлены (контроль по regex `set*`/`with*` — пусто).
- **PHPDoc сохранён**: `@param`-доки конструкторов не тронуты; array-shape-доки (`list<...>`, `array<string, ...>`) продублированы на геттерах — это улучшение контракта. PHPDoc параметра `taskAddendum` в `DynamicLoopContextVo` сохранён на конструкторе, на геттере — краткое резюме. Классовые доки `StaticProcessResultVo` и `DynamicBudgetCheckVo` синхронизированы с новыми именами геттеров (`shouldRetry` → `isRetryNeeded` и т.п.) — согласованность документации соблюдена.

Семантические переименования геттеров относительно имён свойств (конвенции соответствуют, конструкторы не тронуты):

### 🟡 CR-1 (обязательно перед PR): маркер `.make-check.json` неконсистентен

Факты:
- `.make-check.json` — **неотслеживаемый** файл (`??` в `git status`), содержит `{"commit":"1c6199ca…","epoch":1795754898,…}` — ссылается на текущий HEAD (`chore(todo): start TASK-…`), при этом **все кодовые правки не закоммичены**.
- Контракт CI (`bin/local-check-proof`): маркер должен ссылаться на **последний кодовый коммит ветки** (`HEAD^` финального коммита PR), а сам маркер коммитится **последним коммитом PR**.

Следствие: если закоммитить рефакторинг (коммит X) и следом закоммитить текущий маркер, job `local-check` упадёт — маркер ссылается на `1c6199ca`, а не на X. Маркер был сгенерирован на грязном дереве и к моменту открытия PR гарантированно устареет.

**Запрос на изменение (процессное, не код):**
1. Закоммитить кодовые правки рефакторинга (Conventional Commits, например `refactor(domain): make VO properties private with getters / перевод свойств VO в private с геттерами (TASK-techdebt-vo-private-properties)`).
2. Повторно выполнить `make check` на этом коммите (маркер перезапишется с SHA кодового коммита).
3. Закоммитить обновлённый `.make-check.json` **последним коммитом PR**.
4. Перевести задачу в `done`, перенести в `todo/done/`, заполнить поле `PR`, обновить ссылки — до запроса апрува (регламент AGENTS.md).

Файл/строка: `.make-check.json:1` (весь файл), `bin/local-check-proof:27-33` (контракт сверки SHA).
