## 5. Почему подавление действительно избыточно (проверка безопасности типов)

| Звено | Тип | Источник |
| :--- | :--- | :--- |
| `DynamicLoopSessionReaderInterface::getRoundFiles()` | `list<array{…18 полей, invocation?: string}>` — закрытая форма | [DynamicLoopSessionReaderInterface.php](../../../../src/Module/DynamicLoop/Domain/Service/Session/DynamicLoopSessionReaderInterface.php) |
| `ChainSessionReader::getRoundFiles()` | `array_values()` закрытого `array<int, array{…}>` → `list<array{…}>` | [ChainSessionReader.php](../../../../src/Module/DynamicLoop/Infrastructure/Service/ChainSessionReader.php) |
| `DynamicLoopExecution::restoreFromRoundFiles()` | принимающая форма `list<array{…, ...}>` — открытая (`...` разрешает дополнительные поля) | [DynamicLoopExecution.php](../../../../src/Module/DynamicLoop/Domain/Entity/DynamicLoopExecution.php) |

Передача более конкретной закрытой формы в открытую принимающую форму — совместимое присваивание; привести аргумент («coercion») больше не требуется. Это подтверждает вердикт диагностики Т6 задачи-источника и объясняет, почему `ArgumentTypeCoercion` не возникает. Независимый прогон Psalm без подавления — чистый (см. §6), то есть цель задачи достигнута: проверка типов снова охватывает восстановление цикла.

Побочно: ранее при закрытой принимающей форме Psalm давал `InvalidArgument` (зафиксировано в истории задачи-источника, `done/TASK-techdebt-getroundfiles-contract.todo.md`, стр. 168–169, 211). После решения DS «Вариант A» (открытая форма `...`) исчез и `InvalidArgument` — текущий прогон это подтверждает.
