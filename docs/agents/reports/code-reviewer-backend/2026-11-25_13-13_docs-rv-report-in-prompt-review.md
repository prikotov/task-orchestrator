## Замечания

### 🟡 CR-1. SKILL.md, строка 120 — скобка «(первый проход ревью задачи)» сужает требование относительно постановки

Текст: «Полный RV (первый проход ревью задачи) сохраняет отчёт файлом…». Постановка (Expected Result) требует файл от **каждого** полного RV; Must 1 не ограничивает полный RV первым проходом. Классификатор (строка 111) отдаёт тип прохода запускающему: после существенной доработки тимлид вправе назначить повторный **полный** RV — он не является «первым проходом» и не подходит под определение верификационного («без полного перепрохождения»). Скобка создаёт противоречие и лазейку: «это не первый проход — правило не про меня». Вторая фраза правила («короткий вердикт… только для верификационного прохода») требование удерживает, но задача существует именно потому, что мягкая/неоднозначная формулировка уже трижды не сработала.

**Запрос на изменение:** убрать скобку «(первый проход ревью задачи)» либо заменить определением через содержание прохода, например «(полное прохождение проверок ревью)». Правка одной строки, состав проверок и модель не меняются.

### 🟡 Рекомендация тимлиду (не замечание к исполнителю). SKILL.md, строка 142 — контрольная точка без области действия «RV-F бэка»

Пункт «Файл отчёта полного RV существует и заполнен» сформулирован универсально, тогда как правило в шаблоне (строка 120) явно ограничено: «Требование действует для RV-F бэка». При составе ревью без RV-F бэка (например, только RV-A архитектора) пункт либо неисполним (файл никто не обязан создавать), либо провоцирует «файл-для-галочки» — риск 1 постановки. Формулировка дословно предписана Must 1, реализация постановке соответствует — это замечание к самой модели, принятой на PM3. Решение — за тимлидом: уточнить пункт (например, «…если матрица RACI требовала полного RV-F бэка») отдельной правкой в рамках модели или зафиксировать осознанное отступление в задаче.
