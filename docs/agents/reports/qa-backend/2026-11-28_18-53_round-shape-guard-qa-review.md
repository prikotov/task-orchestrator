### 🔵 QA-3 (наблюдение, не блокирует, пре-существующее). Пустой `error_message` не переживает resume — семантика не закреплена

**Что:** probe-прогон: `logRound(isError: true, errorMessage: '')` (и `errorMessage: null` — дефолтный путь, `ChainSessionWriter.php:116` `?? ''`) пишет в `session.json` `"error_message": ""`; при resume `parseRoundFiles()` отбрасывает ключ (`!== ''`, `ChainSessionWriter.php:317`); после перезаписи ключ исчезает. Public-форма in-process (ключ присутствует, `''`) и после resume (ключ отсутствует) различаются. Потери информации нет (`''` не несёт данных, поле в каноне опционально) — это нормализация «пустое = отсутствие», пре-существующая на `main`; данная задача её не вводила.
**Почему вне границ:** задача требует roundtrip записанных полей с содержательными значениями; roundtrip-тест использует непустое сообщение (`'Agent returned an error.'`). 18-полевой состав и мутационная сензитивность не затронуты.
**Запрос (опционально):** закрепить нормализацию тестом — error-раунд с `errorMessage: ''` в `ChainSessionWriterRoundTripAllFieldsTest` с явным `assertArrayNotHasKey('error_message', …)` после resume; либо задачей в `todo/` (кандидат — вместе с проверкой симметрии `error_message: ''` при записи/чтении). Требовать в этом PR не считаю.

### 🔵 Примечание без запроса на изменение (будущий триггер). Регэксп сторожа и вложенные скобки

`/array\{system:.*?\}/s` (нежадный, до первого `}`) корректен для текущей плоской формы: канон без вложенных `array{…}`, любая копия обязана быть байт-в-байт равной канону, инвентарный assert ловит добавление/удаление копий. При появлении вложенного типа (закреплённый триггер «19-е поле») извлечение усечётся на первом `}` — байт-идентичность де-факто ослабнет молча. Действие не требуется сейчас; при срабатывании триггера пересмотреть регэксп (учитывать вложенность) в рамках той же задачи расширения формы.
