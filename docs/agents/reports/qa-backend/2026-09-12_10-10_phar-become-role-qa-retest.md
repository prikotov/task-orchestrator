- запуск копии из B без `--force` → ✅ exit 1 честный конфликт (дефект давал exit 0 с ложным «уже установлен»);
- `--force` из копии B → ✅ привязка = B (дефект перезаписывал её на путь старого A), `become-role.sh` зелёный через B.

**Негативный контроль (выполнен QA лично):** временный откат изоляции в `writableRoot()` к хешу только по host-проекту (одна строка, замена байт-в-байт контролировалась) → пересборка → дефект воспроизводится один-в-один: `mv` A→B, `agent:init --force` из B = exit 1 «Встроенный skill become-role не найден или неполон в PHAR» — та же ложная диагностика, что в исходном отчёте. После контроля `src/Kernel.php` восстановлен байт-в-байт (проверка sha256: ЦЕЛ), PHAR и тестовые каталоги удалены. Вывод: зелёный результат шагов 1–7 — заслуга изоляции, а не совпадение.
