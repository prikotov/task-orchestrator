## 1. Полнота тест-покрытия сценария resume

`resumeRestoresInvocationAndPreservesItThroughSessionJsonRewrite` (`tests/Unit/Infrastructure/Service/Chain/ChainSessionReaderRoundFilesContractTest.php:171–215`) покрывает **все четыре звена** целевого потока:

| Звено | Тест | Итог |
| :--- | :--- | :--- |
| Свежая запись: `logRound(invocation: …)` → `session.json` | `:179–198` — запись + `updateSessionState(1)` + декодирование `session.json`, проверка `rounds[0]['invocation']` | ✅ |
| Resume: новый `ChainSessionLogger` + `resumeSession()` | `:200–204` — второй логгер на тех же путях (эмуляция перезапуска процесса) | ✅ |
| Восстановление `invocation` | `:205–209` — `getRoundFiles()[0]['invocation']` = литерал `'agent:codex run 42'`; дополнительно `assertCount(1)` и `array_is_list` (контракт list 0..n-1) | ✅ |
| Повторная запись `session.json` без нового раунда | `:212–214` — `updateSessionState(1)` → повторное декодирование → значение пережило перезапись | ✅ |

Качество ассертов: сравнение с литералом (не с самим собой); `?? null` не маскирует отсутствие ключа — при потере `invocation` ассерт падает как `null !== 'agent:codex run 42'` (подтверждено мутант-1, §4). Подлинность покрытия подтверждена экспериментально.

**Факт:** поведение обоих случаев верное (probe, §2), расхождение — только в отсутствии фиксации.
**Запрос:** расширить `resumeRestoresInvocationAndPreservesItThroughSessionJsonRewrite` вторым раундом с `invocation: ''` и error-раундом с `invocation` (см. QA-2) — либо вынести в отдельный тест в том же файле. Альтернатива — задача в `todo/` с пометкой, что DS-контракт временно проверяется probe-прогоном этого отчёта.
