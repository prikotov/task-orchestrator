## 1. Назначение и границы

Ретроспектива — самая контекстоёмкая работа тимлида: файлы сессий, архив ретро, реестр, артефакты. Модель переводит **исполнение** ретро в изолированный контекст сабагента, не меняя содержания шагов, шаблона, справочников и правил реестра. Ответственность по RACI сохраняется за ролью тимлида: сабагент запускается с файлом роли тимлида.

**Меняется:** раздел «Как использовать» `SKILL.md` — добавляется норма исполнения через сабагента и формат входа; возможно по одному указателю в полном и сессионном режимах.

**Не меняется:** шаги 1–8, сессионные шаги С1–С4, шаблон, справочники `assets/`, правила реестра, скилл `run-subagent`.

## 2. Решения

**Решение 2.1 (норма исполнения).** Ретроспективу проводит сабагент с ролью тимлида, запущенный через `run-subagent`. Обоснование нормы — контекстоёмкость: первоисточники (файл сессии целиком, архив ретро, реестр) читаются в изолированном контексте, рабочая память сессии-инициатора не расходуется; сабагент смотрит на сессию без предвзятостей инициатора. Дополнение к норме: исполнение в текущей сессии — исключение для заведомо лёгких случаев (нет чтения журналов сессий, минимум артефактов); факт исключения фиксируется фразой в резюме ретро («проведено в текущей сессии как лёгкий случай»), по умолчанию — сабагент.

**Решение 2.2 (вход сабагента).** Инициатор передаёт сабагенту два элемента:
1. **реквизит сессии агента** — id сессии или путь к её файлу; выдаётся инфраструктурой агента (у pi — файл `~/.pi/agent/sessions/<...>.jsonl`; у других агентов — их хранилища, включая базы данных), инициатор его не придумывает, а берёт у инфраструктуры. Для полного режима предмета из нескольких сессий (эпик) реквизит задаёт **якорную сессию** — детерминированную точку входа; остальные первоисточники сабагент собирает сам по Шагу 1, перечень от инициатора не требуется (не смещать полноту на инициатора и не возвращать его предвзятость);
2. опционально — **артефакты работы**: задача, эпик, PR (ссылки).

Отдельная передача контекста не требуется: файл сессии содержит всё общение агента целиком (диалог, вызовы инструментов, результаты, обещания) — сабагент читает его сам. Формулировка входа не привязана к одному инструменту: «реквизит сессии, выданный инфраструктурой агента».

**Решение 2.3 (выход сабагента).** Сабагент выполняет шаги режима (полного или сессионного) без изменений и возвращает инициатору компактное резюме (формат Шага 8 полного режима / итоги мини-режима) **с путями созданных артефактов** — инициатор проверяет их фактическое наличие (защита от случая «резюме выдано, файл не создан» — запись реестра от 2026-10-26). Файл ретро и запись реестра создаются по штатным правилам. **Сабагент не коммитит и не пушит** — публикация набора изменений (файл ретро, реестр, эскалационные предложения) выполняет инициатор по регламенту; одобренные PR не трогаются.

**Решение 2.4 (равенство режимов).** Оба режима исполняются сабагентом одинаково; в сессионном режиме ключ сессии — тот же реквизит сессии из Решения 2.2 (приоритет источников ключа из модели сессионного режима сохраняется: каталог запуска сабагента → журнал сессии → нормализованный диапазон; при ретро по собственной сессии инициатора реквизитом служит её файл).

**Решение 2.5 (место в SKILL.md).** Норма и формат входа — в разделе «Как использовать» (2–4 предложения + указатели); в начале полного режима и сессионного режима — по одному предложению-указателю «исполняется сабагентом с ролью тимлида (см. „Как использовать“)». В норму или указатель сессионного режима входит предложение-мостик: «переданный реквизит — источник ключа по приоритету секции „Ключ сессии“; id нормализуется в абсолютный путь». Объём DC включает обобщение формулировки источника 2 в секции «Ключ сессии» (журнал сессии раннера: у pi — файл, у других агентов — их хранилища) до инструменто-нейтральной. Новых файлов не создаётся; объём — минимальный.

## 3. Состав консультантов

- **PM1 (консультации):** аналитик и архитектор — обязательные.
- **PM2 (проверка):** аналитик — A/R; тестировщик — сценарии отказов: сессия не найдена по реквизиту, файл недоступен, агент с хранением в БД, реквизит передан с ошибкой, лёгкий случай исполнен в текущей сессии без фиксации исключения, резюме выдано — а файл ретро/запись реестра не созданы, реквизит собственной сессии инициатора неопределим.
- **PM3–PM5:** по RACI.

## 4. Критерии принятия (PM3)

- [ ] Норма сабагента сформулирована без привязки к конкретному инструменту агента.
- [ ] Вход — только реквизит сессии + артефакты; никакой передачи контекста помимо них.
- [ ] Содержательные шаги ретро не меняются.
- [ ] Замечания обязательных консультантов PM1 и проверяющего PM2 разрешены или вынесены пользователю.
