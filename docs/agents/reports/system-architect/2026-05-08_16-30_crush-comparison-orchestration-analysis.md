# Архитектурный анализ §3 «Оркестрационные возможности» — crush-comparison.md

**Роль:** Архитектор Гэндальф
**Дата:** 2026-05-08
**Объект:** `docs/research/framework-comparisons/crush-comparison.md`, §3 (строки 106–690)
**Задача:** Анализ полноты описания оркестрационных возможностей, исправление слабых мест

---

## Методология

Анализ проводился по следующим критериям:
1. **Полнота терминальных условий** — все ли условия завершения описаны для каждого паттерна
2. **Edge cases** — учтены ли граничные сценарии
3. **Архитектурные trade-offs** — обозначены ли компромиссы
4. **Ограничения** — явно указаны ли пределы каждого паттерна
5. **Полнота покрытия** — все ли значимые оркестрационные паттерны Crush описаны

---

## Найденные слабые места и исправления

### 1. §3.1 Agent Loop — неполные терминальные условия

**Проблема:** Описаны `StopWhen` условия (summarization, loop detection), но не описано основное терминальное условие (LLM вернул текст без tool calls). Отсутствует анализ max steps limit — критический механизм безопасности.

**Исправление:** Добавлена таблица «Терминальные условия» с 4 условиями завершения. Явно отмечен архитектурный зазор: отсутствие max steps limit — единственная защита от бесконечных уникальных шагов — loop detection, которое ловит только циклы.

### 2. §3.3 Sub-Agent — неполный анализ параллелизма и вложенности

**Проблема:** `fantasy.NewParallelAgentTool` упомянут в одной фразе, но не раскрыт. Глубина вложенности не проанализирована. Timeout субагентов не рассмотрен.

**Исправление:** Добавлены подразделы:
- **Параллелизм субагентов** — Coder может запускать несколько Task-агентов, но без shared state между ними
- **Глубина вложенности** — только один уровень, Task agent не имеет tool `agent`
- **Timeout субагентов** — не документирован, потенциальная проблема

### 3. §3.5 Auto-summarization — неполный анализ edge cases

**Проблема:** Не описано, что происходит при повторном превышении контекста после summarization. Не отмечена стоимость summarization (large model, полный контекст). Не проанализирована потеря granularity.

**Исправление:** Добавлен подраздел «Edge cases и ограничения» с тремя аспектами: recursive summarization, стоимость, потеря granularity. Дополнена оркестрационная значимость анализом trade-off (необратимое сжатие vs sliding window vs external memory).

### 4. §3.6 Loop Detection — неполное описание реакции

**Проблема:** Описано как обнаруживается цикл, но не описана реакция: что происходит с сессией, может ли пользователь продолжить.

**Исправление:** Добавлен подраздел «Реакция на обнаружение цикла» — агент останавливается, но сессия не завершается. Добавлен подраздел «Ограничения сигнатурного метода» — exact-match only, не ловит семантические циклы.

### 5. §3.8 Permission System — не проанализирована persistence

**Проблема:** Grants хранятся in-memory — при перезапуске теряются. Не отмечено как ограничение.

**Исправление:** Добавлен подраздел «Persistence и ограничения» — in-memory storage, нет persistent allow-list между сессиями (кроме конфига).

### 6. §3.9 Orphaned Tool Call Recovery — не отмечена проблема side effects

**Проблема:** Synthetic result предлагает модели retry, но retry может повторить side effects. Не проанализировано.

**Исправление:** Добавлен подраздел «Ограничения и side effects» — нет rollback, нет идемпотентности, ответственность за повтор делегирована модели.

### 7. Добавлен §3.14 Error Handling & Provider Resilience

**Проблема:** Критический оркестрационный паттерн полностью отсутствовал. Не описано: retry, fallback, circuit breaker, error classification.

**Исправление:** Добавлен новый параграф с анализом:
- Provider-level retry (через fantasy)
- Ограниченный dual model fallback (только для заголовков)
- Provider media workarounds (preventive)
- Явно отмечены отсутствующие: cross-provider fallback, circuit breaker, semantic validation

### 8. Добавлен §3.15 Cancel & Graceful Shutdown

**Проблема:** Паттерн отмены и graceful shutdown — необходимый элемент оркестрации — не был описан. Cancel упоминался вскользь в §3.4, но полный lifecycle не анализировался.

**Исправление:** Добавлен новый параграф с анализом:
- Context-based cancellation (Go idiom)
- Cascading cleanup: queue flush, tool interrupt, sub-agent cancel
- Гарантии: queue flush — гарантирован, tool interrupt — best effort, rollback — нет
- Cost propagation при отмене субагентов

### 9. §5 Сводка обновлена

Добавлены 2 новые строки: Error Handling (⚠️) и Cancel (✅). Обновлена значимость Cost Tracking.
