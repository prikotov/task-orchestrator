## Внесённые правки (9 блоков)

### Структурные изменения
- Заголовок «Оркестрационная значимость» → «Архитектурный анализ» во всех 9 подразделах
- В каждый подраздел добавлен блок «**Ограничения:**» с описанием tradeoffs

### §3.1 DAG Workflow Execution
- Удалена фраза «Наша модель оркестрации — линейные цепочки»
- Добавлен перечень значений `trigger_rule`: `all_success`, `none_failed`, `none_failed_min_one_success`, `any_success`, `all_done`
- Добавлено ограничение: DAG не поддерживает циклы, отладка параллельных веток сложнее

### §3.2 Loop Nodes
- Удалена ссылка на «fix_iterations»
- Расширено описание: dual exit strategy, fresh_context semantics, interactive mode
- Добавлено ограничение: fresh_context → потеря контекста, max_iterations → failed

### §3.3 Human-in-the-Loop
- Развёрнут из одного предложения в полный анализ: approval gate pattern, on_reject cycle, interactive loops
- Добавлено ограничение: невозможно автономное выполнение, max_attempts exhaustion

### §3.4 Isolation
- Удалена фраза «В PHP нет worktrees нативно»
- Структурированный список гарантий + упоминание IIsolationProvider
- Добавлено ограничение: только FS-изоляция, нет сетевой, O(repo size) по диску

### §3.5 Error Classification (значительное расширение)
- Добавлена колонка «Retry-поведение» в таблицу (FATAL → no retry, TRANSIENT → exponential backoff, UNKNOWN → cautious)
- Добавлено описание mechanism: `classifyError()` в `executor-shared.ts`, pattern matching
- Добавлен архитектурный анализ: circuit breaker pattern на уровне узла
- Добавлено ограничение: эвристика, не формальный контракт; классы захардкожены

### §3.6 DAG Resume on Failure
- Исправлен баг форматирования (отсутствующая пустая строка перед ### 3.7)
- Развёрнут из одного предложения: checkpoint-and-resume pattern, idempotent replay
- Добавлено ограничение: зависимость от артефактов, duplicate side effects

### §3.7 Output Substitution
- Развёрнут из одного предложения: data binding pattern, dot-notation, data-flow graph
- Добавлено ограничение: сырой текст без output_format, нет агрегации, cycle detection

### §3.8 Structured JSON Output
- Удалена фраза «Сейчас мы полагаемся на текстовый вывод runner'ов»
- Добавлен анализ: contract enforcement pattern, provider-specific enforcement levels
- Добавлено ограничение: best-effort на Pi, single-node scope validation

### §3.9 Per-Node Provider/Model
- Удалена субъективная оценка «ценная оптимизация»
- Добавлен анализ: heterogeneous routing pattern, cost/quality optimization
- Добавлено ограничение: потеря контекста при переключении, бюджетный контроль только Claude

Все ссылки на task-orchestrator из §3 удалены. Каждый подраздел §3 теперь содержит объективный анализ паттерна (что он даёт) и ограничения (какие tradeoffs). §3.5 расширен с 5 строк до полноценного раздела. Баг форматирования §3.6 исправлен.
