## Проблемы

- 🟡 **Подготовка простого исправляющего релиза была переоркестрирована.** От слияния #371 (`21:39:30 +07`) до финального успешного прогона #372 (`22:25:24 +07`) прошло 45 минут 54 секунды. Из них 11 последовательных запусков сабагентов заняли суммарно 24 минуты 58 секунд. Для трёх документационных файлов выполнены отдельные запуски: реализация, самопроверка, три прохода независимого ревью, две доработки и три синхронизации метаданных задачи. Основная причина — отсутствие короткого специализированного процесса подготовки исправляющего релиза. Статус в [реестре](RETRO-ROADMAP.md): `watch`.

- 🟡 **Первоисточники автоматизации выпуска проверены поздно.** Первый черновик и самопроверка не учли, что `.github/workflows/release-phar.yml` уже создаёт выпуск GitHub через `softprops/action-gh-release`; это обнаружилось только во втором независимом ревью. Аналогично метка и ответственный исправлялись после первого полного черновика. Корень — исполнителю не была задана обязательная предварительная сверка источников до записи файлов. Статус в [реестре](RETRO-ROADMAP.md): `watch`.

- 🟡 **Даты UTC проверены после успешной непрерывной интеграции.** Временные метки Unix в задаче были корректными, но человекочитаемые даты записаны в `+07`, тогда как `todo-md` ожидает UTC. Исправление потребовало отдельного коммита и нового прогона. Статус в [реестре](RETRO-ROADMAP.md): `watch`.

- 🟢 **Внешний HTTP 504 нельзя было перезапустить штатно от приложения GitHub.** Первый прогон #372 упал только на загрузке зависимостей Composer: несколько запросов к `api.github.com` вернули HTTP/2 504. Команда `gh run rerun --failed` получила `Resource not accessible by integration`, поэтому для нового запуска пришлось создать пустой коммит. Второй прогон прошёл. Статус в [реестре](RETRO-ROADMAP.md): `watch`.
