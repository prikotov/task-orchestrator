## Что прошло хорошо

- Калибровка soft-timeout ×1.5 (600→900→1350с) по правилу [`task-via-subagents/SKILL.md`](../../skills/task-via-subagents/SKILL.md) → каждый перезапуск сохранял и наращивал прогресс (uncommitted-состояние сохранялось: №2 — оба класса разбиты; №3 — PHPMD 0), ни одна итерация не начата с нуля → повторять при каждом soft_timeout.
- Контроль по артефактам после таймаута доработки вместо автоматического перезапуска: после доводящего C0 (601с) инициатор сам закрыл верификацию — точечный PHPCS, `validate-language`, полный `make check` (1759 тестов OK, записи 10:08:40–10:11:21Z); после доработок 17:28 и 18:08 — проверка diff по каждому CR + `make check` (1760/1761 тестов) → заменены минимум два потенциальных перезапуска сабагента → повторять, когда остаточный скоуп — верификация (предложение 3).
- CR-решения по конвенциям с фиксацией в разделе 9 задачи: Helper-паттерн (`DynamicRoleCommandHelper`/`DynamicRoundResultHelper` в `Domain/Helper`, по [helper.md](../../conventions/core-patterns/helper.md)), единый механизм инлайн-подавлений (`@SuppressWarnings("PHPMD.StaticAccess")` с комментарием-причиной в `PharRunningPathResolver:25`, запись удалена из baseline), переименование `YamlDynamicPromptsResolverService*` → `ResolveYamlDynamicPromptsService*` по [service.md](../../conventions/core-patterns/service.md) → оба ревью закрыты без третьего цикла доработок; все решения трассируются в задаче → повторять при каждом CR-конфликте «практика vs конвенция».
- Двухтрековое ревью RV-F + RV-A с точечными recheck → 6 CR двух разных оптик (конвенции/тесты против архитектуры/согласованности), recheck 156с и 250с вместо полных повторов → повторять по регламенту двух треков (TASK-chore-two-track-code-review, PR #488).
- Уроки реестра применены при запуске ретро: `-s 1800` для C3 и «читай ВЫБОРКОЙ (rg/head/tail)» в промпте соответствуют записи «Таблица таймаутов…» [RETRO-ROADMAP.md](RETRO-ROADMAP.md) («контекстоёмкие ретро ≥1800с + режим экономии чтения») → запуск №2 стартовал с калиброванным лимитом → повторять при каждом контекстоёмком запуске.

## Важные комментарии

- **Guardrails-аудит (Шаг 3):** фактический состав проверок прочитан из первоисточников — `make check` (Makefile:121–126) включает coding-standard-verify/di-check, phpstan, deptrac, psalm, phpmd, phpcs, md-links, validate-todo, validate-roles, validate-language, tests; CI — `ci.yml`, `release-phar.yml`, `secret-scan-pr-content.yml`; хуки — pre-commit, commit-msg (gitleaks); `.gitleaks.toml` на месте. Неподключённых или молча сломанных проверок по предмету не выявлено; новых механических правил, требующих новой проверки, не зафиксировано.
- **Конвенции:** нарушений не зафиксировано — оба ревью и финальные recheck подтвердили соответствие (Deptrac 0, PHPCS 0, PHPMD 0 без baseline); напротив, CR-решения выровняли код с конвенциями (Helper, service.md).
- Реквизит ретро описывал якорную сессию как «~10+ МБ» — фактически 594 КБ / 207 записей; журнал прочитан целиком, на выводы не повлияло. Причина расхождения не установлена (неподтверждено).
- Stall-убийство ретро №1 — не повтор записей N-2/N-4 (флаки liveness-тестов stall): причинная цепочка — вложенный блокирующий вызов рекурсии, не провайдерский hang.
- Валидатор todo-md штатно требует переноса файла в `todo/done/` до проставления статуса `done` — сработало как ожидается (записи 12:05:51–12:05:56Z).
