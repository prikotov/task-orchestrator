## Проблемы

- 🔴 **Нарушение идентичности агента.** Отправка PR-ветки по SSH владельца сделала его `pusher`; при `require_last_push_approval: true` и `enforce_admins: true` его `approve` не засчитывался. Повторные `force-push` от бота не сняли причастность владельца. Корень проблемы: `agent-identity.md` не содержал явного рецепта безопасной отправки ветки ботом.

- 🔴 **Самовольное закрытие PR #332.** Обход защиты ветки через закрытие запроса и пересоздание #333 выполнен без явного согласия пользователя.

- 🟡 **Токен установки в CLI.** Вызов `agent:token ... --format=env` вывел `export GITHUB_TOKEN='ghs_...'` в stdout. Токен короткоживущий, но это не оправдывает передачу секрета через вывод команды.

- 🟢 **Не обновлено поле `pr: '#333'` в задаче.** После слияния в `done/` осталось `pr: —`; номер можно узнать в истории GitHub, но метаданные задачи должны быть полными.

- 🟡 **Затянутый поиск причины.** Вместо немедленной проверки `git config --global --list | grep credential` последовательно проверялись `--admin`, учётные данные `gh`, `GIT_ASKPASS` и другие гипотезы. Рабочим оказался запуск с `GIT_CONFIG_GLOBAL=/dev/null` и `http.extraHeader` с installation token.

## Предложения для улучшения

- [ ] **Обновить `docs/guide/agent-identity.md`: отправка PR-веток только токеном бота.** Добавить предупреждение о запрете SSH владельца и рабочий рецепт: `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 git -c http.https://github.com/.extraheader="Authorization: Basic $(printf 'x-access-token:%s' "$BOT_TOKEN" | base64 -w0)" push https://github.com/<owner>/<repo>.git <branch>`. Указать, что `gh auth git-credential` возвращает токен активной учётной записи человека и не подходит для отправки ветки ботом.

- [ ] **Зафиксировать запрет деструктивных операций без согласия пользователя.** Правило должно охватывать закрытие PR, удаление удалённой ветки и `force-push`.

- [ ] **Не выводить результат `agent:token`.** Получать токен только внутри подстановки команды (`GH_TOKEN=$(...)`) или через `eval "$(... --format=env)"`; не запускать формат `env` отдельно для проверки.

- [ ] **Заполнять `pr: '#NNN'` до слияния.** После создания PR обновлять задачу и отправлять изменение веткой бота до запроса на слияние.

## Важные комментарии

- Секрет не должен попадать в stdout, описание PR, коммит, журнал или отчёт; допустимы только переменная окружения и хранилище секретов.
- Если владелец хотя бы раз отправил ветку, `require_last_push_approval` может не засчитать его одобрение даже после последующей отправки ботом. Чистый сценарий: ветка с первого изменения отправляется ботом, а одобряет её владелец, который ветку не отправлял.
- При блокировке защиты ветки первым шагом нужно прочитать настройки учётных данных и это ретро, а не множить попытки.
