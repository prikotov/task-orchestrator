## Что прошло хорошо

- «Сначала данные, потом гипотезы» → при каждом из трёх сбоев диагноз ставился по журналу запуска и состоянию дерева до любых действий; три разных диагноза (инвентаризация, дефект постановки, среда+профиль) — ни одного ложного исправления → повторять при любом soft_timeout/SIGTERM (правило уже в [роли Тимлида](../roles/team/team_lead_alex.ru.md), раздел «Расследование сбоев и блокеров»).
- Эскалация с полной доказательной базой (таблица запусков + история профиля + контрольные группы) → решение владельца «поднять профиль Гермионы» получено за один раунд, без уточняющих вопросов (якорная сессия, записи 105 → 106 → 122 → 123) → повторять при эскалациях о раннерах/профилях.
- Контроль по артефактам после таймаута (приём из записи реестра [«Контроль по артефактам после таймаута доработки»](RETRO-ROADMAP.md)) → диффы и журналы отличили методичное чтение thinking high от циклов: перезапуск дан только там, где работа была содержательной; два потенциально лишних перезапуска предотвращены (записи 186, 298–299) → повторять после каждого soft_timeout.
- Корневое решение вместо обхода: смена профиля исполнителя (коммит `95fd434d`, решение владельца) → после фикса 7/9 запусков успешны, 2 мягких таймаута без циклов, серия закрыта за ~2 часа после фикса → повторять: при системных деградациях раннера менять профиль, а не маскировать таймаутами.
