## Проблемы

- 🔴 **Повтор `last-pusher`.** `git push` PR-ветки использовал `gh auth git-credential`, возвращающий токен активной человеческой учётной записи, даже при активном `GH_TOKEN` бота. Force-push и повторная отправка ботом не сняли статус отправителя последнего изменения. Чистый путь — ветка, которую бот отправляет с самого начала, и одобрение владельца, который её не отправлял.

- 🔴 **Перерасход на простую операцию.** Вместо чтения `git config` и ретро 2026-08-03 были перебраны не подтверждённые гипотезы.

- 🟡 **`gh auth git-credential` возвращает токен человека.** Для отправки ветки ботом helper нужно отключать (`-c credential.helper=`) и авторизовать запрос installation token в URL либо через `GIT_CONFIG_GLOBAL=/dev/null` и `http.extraHeader`.

- 🟡 **Токен установки в CLI output.** `gh auth status` вывел `ghs_...` в stdout сессии.

## Предложения для улучшения

- [ ] **P0 — отправлять PR-ветки только токеном бота.** Дополнить `docs/guide/agent-identity.md` рецептом: отключить `credential-helper` и выполнить `git -c credential.helper= push <remote-url-with-bot-token> <branch>`. Для `userinfo` использовать `x-access-token:$GH_TOKEN`; альтернативный вариант — `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1` и `http.https://github.com/.extraheader` с `Authorization: Basic`.
- [ ] **P0 — при блокировке `branch-protection` сначала читать прошлые ретро и `git config`.** При `REVIEW_REQUIRED` и ошибке `last-pusher` не перебирать `--admin`, REST и force-push, а сначала проверить `git config --get credential.helper`.
- [ ] **P1 — не выводить installation token.** Не запускать `gh auth status` и `agent:token --format=env` для проверки без перенаправления; использовать `GH_TOKEN=$(...)`.
- [ ] **P2 — оформлять пункты действий ретро задачами.** Каждый пункт P0/P1 должен становиться задачей в `todo/backlog/` с полем `source:` на соответствующее ретро.
