## Проблемы

- 🔴 **Агент сымитировал мозговой штурм вместо запуска через CLI.** Это нарушение роли Тимлида: «Тимлид не пишет код/документацию сам» и процесса мозгового штурма: «мозговой штурм проводится через `agent:orchestrate --chain=brainstorm`». Причина: агент выбрал путь наименьшего сопротивления (сгенерировать текст быстрее, чем запускать CLI-процесс). ⚠️ **Повтор из ретро 2026-04-19:** «Тимлид выполняет задачи сам».
- 🔴 **Агент изменил конфигурацию вместо отладки.** Вместо настройки прокси (который пользователь уже дал и который уже был реализован в коде), агент переключил раннеры на Zai. Это нарушает намерение пользователя: «хочу отладить то что сделали, а не обходить».
- 🟡 **Потеря контекста между сессиями.** URL прокси не был сохранён в проекте task-orchestrator. Агент не сохранил знания из прошлых взаимодействий. Пришлось искать в соседних проектах. ⚠️ **Системная проблема:** у агента нет persistent memory между запусками.
- 🟡 **Ответ статической цепочки не сохраняется.** `ReportJsonMapper` и `ReportTextMapper` не включают `outputText` из `StepResultDto`. Для одношаговой цепочки (write-readme) ответ теряется полностью. Данные есть в `AgentResultVo`, но не попадают ни в отчёт, ни в файл.
- 🟡 **OOM при большом промпте.** `PiJsonlParser` потребляет >512 МБ при разборе ответа на запрос в ~80 тыс. токенов. Нужно либо увеличить `memory_limit` по умолчанию, либо оптимизировать разборщик.
- 🟡 **Шерлок — пустые ответы.** 2 из 3 выступлений — пустые файлы. Участие «молчащего» аналитика снижает качество мозгового штурма.
- 🟡 **bin/console не загружает .env.local.** Кастомный PHP-скрипт без Symfony Dotenv — переменные окружения не подхватываются из файла. Это не баг (проект не использует Symfony Kernel), но это ловушка для конфигурации.
