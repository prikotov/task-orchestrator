# Become Role

Войти в роль: подгрузить файл роли и развернуть её skills (навыков) в контексте
агента. Сам `become-role` доступен агентам через `.agents/skills/`, а
role-специфичные skills не требуют нативной автозагрузки — работает и в pi,
и в codex через чтение файлов и `bin/console`.

> **Предусловие.** Каталог `.agents/` создаётся per-environment (он в `.gitignore`).
> Если `.agents/skills/become-role` отсутствует после клонирования, выполни
> `bin/console agent:init` (см. `AGENTS.md`, раздел «Скиллы ролей»).

## Когда использовать

- Пользователь обращается к роли по имени или прямо просит её принять: «Тимлид, запусти эпик», «Аналитик, разбери требования», «возьми на себя роль …».
- Промпт подразумевает вид задач, закреплённый за ролью: «сделай code review», «напиши тест-план», «задокументируй изменение».

## Имена ролей

Имя роли = имя файла роли без локали и расширения. Например:

- `docs/agents/roles/team/team_lead_alex.ru.md` → `team_lead_alex`
- `docs/agents/roles/team/backend_developer_levsha.ru.md` → `backend_developer_levsha`

Полный список ролей — в `AGENTS.md` (раздел «Роль»); файлы ролей лежат в `docs/agents/roles/team/`.

## Как использовать

**Шаг 1.** Определи имя роли (snake_case), если оно не названо явно — по
описаниям ролей в `AGENTS.md` (раздел «Роль»). При сомнении бери `team_lead_alex`
(дефолт проекта).

**Шаг 2.** Вызови скрипт входа в роль, передав имя роли. Путь — от корня проекта:

```bash
docs/agents/skills/become-role/scripts/become-role.sh <role>
# или через симлинк .agents/ (как его видит агент):
.agents/skills/become-role/scripts/become-role.sh <role>
```

**Шаг 3.** Действуй по выводу скрипта:

1. **Прочитай файл роли полностью** через `read` (путь указан в выводе) — там
   personality, экспертиза, стиль работы, мини-чеклист роли.
2. **Используй каталог skills** — XML-блок `<available_skills>` в выводе. Если
   блока нет — у роли не объявлены skills; работай только с прочитанным файлом
   роли. Когда задача совпадает с описанием skill, открой его `SKILL.md` (поле
   `<location>`) через `read` **полностью** и следуй инструкциям. Связанные
   файлы (`scripts/`, `references/`) читай только когда они прямо нужны по
   инструкции skill. Не читай все skills роли заранее — только тот, что подходит
   к задаче (progressive disclosure). Относительные пути внутри skill разрешай
   относительно каталога skill (родитель `SKILL.md`).

Резервный путь (fallback), если скрипт недоступен — `bin/console agent:role-skills
<role> --format=block` выведет только каталог skills (без пути к файлу роли);
файл роли поищи в `docs/agents/roles/team/` в порядке `<role>.ru.md` →
`<role>.md` → любой `<role>.<locale>.md`. Если скрипт или команда завершились
ошибкой (роль не найдена, skill не найден, цикл `depends_on`) — остановись и
сообщи ошибку; не угадывай путь или имя (fail-fast).

## Результат

Скрипт ничего не подгружает автоматически — он только печатает путь к файлу
роли и (при наличии) каталог skills. Дальше агент действует сам:

- читает файл роли и работает от лица этой роли;
- видит каталог её skills (`<available_skills>`) и по описанию подгружает нужный
  `SKILL.md` (progressive disclosure).

## Принцип

`become-role` — единственный общий skill: он резолвит skills из frontmatter
роли (с развёрнутыми `depends_on`) и выводит каталог `<available_skills>`,
поэтому role-специфичные skills не нужно размещать в автозагружаемых локациях
(где их увидели бы все роли). Изоляция контекста по роли достигается промптом,
а не фильтрацией автозагрузки.
