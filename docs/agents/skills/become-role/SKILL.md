# Become Role (Войти в роль)

Войти в роль и получить её skills для работы от лица этой роли.

## Когда использовать

Применяй перед работой от лица роли — когда нужно действовать как конкретный член команды (Тимлид, Аналитик, Ревьювер, …):

- пользователь обратился к роли по имени или виду задачи;
- задача закреплена за ролью и требует её экспертизы/стиля;
- прямо просят взять на себя роль.

## Как использовать

**Шаг 1.** Определи роль — по описаниям ролей в `AGENTS.md` (раздел «Роль») или
RACI-матрице. При сомнении бери `team_lead_alex` (дефолт проекта).

**Шаг 2.** Вызови скрипт, передав имя роли или путь к файлу роли:

```bash
# Запускай из каталога скилла (каталог с этим SKILL.md).
scripts/become-role.sh <role|file>
```

Пример вывода (`become-role.sh team_lead_alex`):

```
Роль: team_lead_alex
Файл роли: docs/agents/roles/team/team_lead_alex.ru.md

Следующие skills предоставляют специализированные инструкции для конкретных задач.
Когда задача совпадает с описанием skill — загрузи его SKILL.md инструментом read.
...

<available_skills>
  <skill>
    <name>run-subagent</name>
    <description>Запуск сабагента через pi/codex ...</description>
    <location>/.../docs/agents/skills/run-subagent/SKILL.md</location>
  </skill>
  ...
</available_skills>
```

**Шаг 3.** Действуй по выводу скрипта.

### Войти в роль

1. Прочитай файл роли (путь в выводе) через `read` **полностью**.
2. Файл роли — это личность: personality (черты характера), экспертиза, стиль работы, предпочтения, мини-чеклист.
3. **Войти в роль** — действовать от лица этого персонажа до конца задачи: применяй её personality и стиль в ответах и решениях, опирайся на её экспертизу, не «выпадай» из роли.

### Использовать skills

В выводе XML-блок skills роли (`<available_skills>`): каждый skill описан кратко (`name`, `description`, `location`).

1. Skills даны описаниями, полные тела загружай при необходимости. Не читай все skills заранее.
2. Когда текущая задача подходит под описание skill, загрузи его `SKILL.md` (поле `<location>`) через `read` **полностью** и следуй инструкциям.
3. Связанные файлы skill из `scripts/`, `references/` читай только когда они прямо нужны по инструкции skill.
4. Пути внутри skill (`scripts/…`, `references/…`) лежат рядом с `SKILL.md`, а не в корне проекта. Бери каталог из `<location>` и подставляй перед путём. Пример: `scripts/x.sh` при `<location>` `…/run-subagent/SKILL.md` → `…/run-subagent/scripts/x.sh`.

Если блока `<available_skills>` нет — у роли нет skills; работай только от лица роли.

## Результат

Агент получает путь к файлу роли и каталог её skills: роль читает сам (через `read`), подходящие skills подгружает по описанию.
