# Справочник направлений анализа процесса

Справочник для Шага 3 навыка [`retrospective`](../SKILL.md): признаки семи направлений и методика аудита подключённости проверок. Фактический состав check-команд проекта здесь не хранится — читай первоисточники на каждой ретроспективе.

## Семь направлений

1. **Процессы** — что было неочевидно или нарушалось; таймауты, координация. Пример: цепочка падала на шаге ревью из-за отсутствия таймаута.
2. **Конвенции** — что было неочевидно или нарушалось. Пример: слой Application обратился к Infrastructure напрямую.
3. **Инструменты** — проблемы сабагентов, git, CI; дорогие вызовы инструментов и доступ агента к информации. Нехватка доступа — находка «расширить доступ»; дорогой вызов — «упростить или заменить».
4. **Координация** — ошибки при передаче задач между ролями. Пример: сабагент получил постановку без ограничения объёма.
5. **Повторяющиеся** — проблемы, которые уже были в прошлых ретро; сверяй с `docs/agents/team-retro/`.
6. **Проверки (guardrails)** — подключённость автоматических проверок; методика аудита ниже.
7. **Инструкции** — пустые инструкции (no-ops) и разросшийся стиринг; признаки ниже.

## Аудит подключённости проверок (guardrails)

Сначала прочитай фактические check-команды проекта:

- `Makefile` — цели `check`, `test` и производные;
- `composer.json` — секция `scripts`;
- `.github/workflows/` — задания CI;
- pre-commit хуки;
- `.gitleaks.toml`.

Затем проверь признаки:

- **Не подключена:** команда существует, но не упомянута ни в `make check`, ни в CI, ни в хуках. Для находки достаточно статического чтения этой связки — запуск команды здесь ничего не доказывает.
- **Молча сломана:** проверка подключена, но не ловит нарушение. Подтверждай целевым одноразовым запуском конкретной команды — в идеале на заведомо невалидном образце для «всегда-зелёных» поломок; запуск выполняй в чистом состоянии и не оставляй артефактов в рабочем дереве.

Отсутствие проверки для известного механического правила — тоже находка. Предложение новой проверки допустимо только после сверки с арсеналом выше: не изобретай новую, когда существующая той же цели не подключена.

## Инструкции: no-ops и разросшийся стиринг

- **Пустая инструкция (no-op)** — инструкция, которая ничего не меняет в поведении агента: невыполнимая, дублирующая уже подключённую проверку, декларативная без адресата.
- **Разросшийся стиринг** — большой `AGENTS.md`, дублирование правил между файлами ролей и навыками, правила, пережившие свою ошибку.
