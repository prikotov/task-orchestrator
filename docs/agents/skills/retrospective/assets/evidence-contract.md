# Контракт доказательств (evidence contract)

Справочник для Шага 1 навыка [`retrospective`](../SKILL.md): что считается достаточным доказательством находки и как обращаться с первоисточниками сессии. Доказательство — минимальный указатель (файл + запись или позиция) плюс обезличенная цитата, а не копия всей сессии.

## Границы первоисточников

- Запись сессии хранит раннер агента: у pi — файлы `~/.pi/agent/sessions/<...>.jsonl`; у других агентов — свои хранилища (файлы или база данных). Полный диалог с вызовами инструментов — только здесь.
- Внутренние журналы механизмов оркестратора (шаги цепочки, роли, токены, стоимость — см. [документ наблюдаемости](../../../../guide/observability.md)) — вспомогательный источник метрик, а не запись сессии: долгий поиск подтверждает только трасса вызовов инструментов из журнала сессии.

## Матрица достаточности доказательств

| Тип находки | Достаточное доказательство |
|---|---|
| Задержка шага | Временные метки начала и окончания шага из журнала сессии раннера или вспомогательного журнала метрик оркестратора |
| Повторные ошибочные вызовы | Записи журнала сессии (трасса вызовов инструментов) с указателем на момент |
| Проверка не подключена | Статическое чтение связки: команда существует, но не упомянута ни в `make check`/`Makefile`, ни в CI-заданиях, ни в хуках (запуск команды здесь ничего не доказывает) |
| Проверка молча сломана | Файл конфигурации + целевой одноразовый запуск команды (в идеале — на заведомо невалидном образце для «всегда-зелёных» поломок); запуск выполняется в чистом состоянии и не оставляет артефактов в рабочем дереве |
| Противоречие журнала и артефакта (коммит/PR) | Журнал фиксирует попытки, артефакт — результат: для находки о результате приоритет у артефакта, расхождение — наблюдение в отчёт |
| Долгий поиск файла или факта | Трасса вызовов инструментов из журнала сессии раннера (журналы метрик оркестратора сами по себе не доказывают) |
| Дефект уровня «суждение», пропущенный ревьюером | Указатель на коммит/PR/находку ревью, где дефект прошёл, и место, где он проявился или был пойман позже |
| Пустое или шумящее правило | Указатель на правило + повторяющееся нарушение при живом правиле либо дублирование уже подключённой проверки (со ссылкой на неё) |
| Успешная практика (кандидат на закрепление) | Указатель на коммит/PR/артефакт, где приём сработал, + подтверждённая польза |
| Расхождение вспомогательного журнала метрик и журнала сессии | Приоритет — источник с более полной трассой шага; само расхождение фиксируется наблюдением в отчёте |
| Целевой запуск проверки непомерно дорог или долог | Статус проверки помечается «неподтверждено» с указанием причины; полный прогон не требуется |
| Источник отсутствует или неполон | Вывод явно помечается «неподтверждено», не выдаётся за факт и не додумывается |

## Доказательства без секретов

- В отчёт ретроспективы попадает только безопасный указатель и обезличенное доказательство; копировать чувствительные фрагменты журналов и секретоподобные значения запрещено.
- Граница «секретоподобного» — по паттернам регламента «Работа с секретами» в [`AGENTS.md`](../../../../../AGENTS.md): PEM, токены `ghs_*`/PAT/JWT/API-key, пароли, значения `.env*`.
- При сомнении в нестандартном формате значение обезличивается заместителем (например, `ghs_<redacted>`), а не копируется.

## Если источник отсутствует или неполон

Вывод явно помечается «неподтверждено» — прямо в Шаге 1, не только здесь. Предложение может опираться на неподтверждённую находку, но само помечается «на базе неподтверждённой находки» (см. Шаг 5).
