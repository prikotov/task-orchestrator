# Adopt Role

Вход в роль: подгрузка файла роли и объявление её skills (навыков) в контексте
агента. Сам `adopt-role` доступен агентам через `.agents/skills/`, а
role-специфичные skills не требуют нативной автозагрузки — работает и в pi,
и в codex через чтение файлов и `bin/console`.

## Когда использовать

- Пользователь обращается к роли по имени или прямо просит её принять: «Тимлид, запусти эпик», «Аналитик, разбери требования», «возьми на себя роль …».
- Промпт подразумевает вид задач, закреплённый за ролью: «сделай code review», «напиши тест-план», «задокументируй изменение».

## Как использовать

**Шаг 1.** Определи имя роли (snake_case), если оно не названо явно — по
описаниям ролей в `AGENTS.md` (раздел «Роль»).

**Шаг 2.** Вызови скрипт входа в роль, передав имя роли:

```bash
scripts/adopt-role.sh <role>
```

Скрипт лежит рядом с этим SKILL.md в папке `scripts/`.

**Шаг 3.** Действуй по выводу скрипта:

1. **Прочитай файл роли полностью** через `read` (путь указан в выводе) — там
   personality, экспертиза, стиль работы, мини-чеклист роли.
2. **Используй каталог skills** — XML-блок `<available_skills>` в выводе.
   Когда задача совпадает с описанием skill, открой его `SKILL.md` (поле
   `<location>`) через `read` и следуй инструкциям. Относительные пути внутри
   skill разрешай относительно каталога skill (родитель `SKILL.md`).

Fallback, если скрипт недоступен — `bin/console agent:role-skills <role> --format=block`
выведет только каталог skills (без пути к файлу роли); файл роли определи сам
из `docs/agents/roles/team/<role>.ru.md`.

## Имена ролей

Имя роли = имя файла роли без локали и расширения. Например:

- `docs/agents/roles/team/team_lead_alex.ru.md` → `team_lead_alex`
- `docs/agents/roles/team/backend_developer_levsha.ru.md` → `backend_developer_levsha`

Полный список ролей — в `AGENTS.md` (раздел «Роль»); файлы ролей лежат в `docs/agents/roles/team/`.

## Результат

В контексте агента появляются:

- файл роли (прочитан через `read`) — агент действует от лица этой роли;
- каталог её skills (`<available_skills>`) — агент знает, какие навыки доступны,
  и подгружает их тела по требованию (progressive disclosure).

## Принцип

`adopt-role` — единственный общий skill: он резолвит skills из frontmatter
роли (с развёрнутыми `depends_on`) и выводит каталог `<available_skills>`,
поэтому role-специфичные skills не нужно размещать в автозагружаемых локациях
(где их увидели бы все роли). Изоляция контекста по роли достигается промптом,
а не фильтрацией автозагрузки.
