# Pi Native Rendering

pi рендерит сам — просто выведи в ответе:

- Блок ` ```mermaid ` → ASCII-арт. Типы: flowchart/graph (subgraph, v2-формы), sequence, state, class, er, pie, mindmap, timeline, gitGraph. Стили автора (`classDef`, `:::class`, `style`) применяются best-effort.
- Типы gantt/journey/quadrantChart/sankey в терминале НЕ рисуются — давай исходник или картинку.
- `$...$` и `$$...$$` (LaTeX) → Unicode-вёрстка. Только для математики.
- GFM-таблицы, код с указанием языка → таблица/подсветка.

Каналы: чат — блоки выше, ничего запускать не нужно; картинка в чате — сгенерируй PNG/JPEG и покажи через `read`; `docs/*.md` и PR — mermaid-исходник блоком (GitHub рендерит сам).

Кликабельность (pi рендерит markdown-ссылки в OSC 8; видна только в терминалах с OSC 8): файл — `[подпись](<file:///полный/путь>)` (угловые скобки обязательны при пробелах в пути), web — `[подпись](https://…)`. Только `file://`/`https://` переносимы между терминалами; голый путь — мёртвый текст; относительный (`путь`, `./путь`) и `~/путь` — терминал падает с ошибкой «не удалось распознать схему URI»; `/абсолютный/путь` без схемы открывается в ghostty, но вне стандарта OSC 8 — в ответах не использовать; ссылки в код-блоках не кликабельны; raw OSC 8-последовательности не использовать. Знаки препинания предложения — за закрывающей скобкой: `[текст](<file:///путь>).` — в href попадает ровно то, что стоит в `(…)`; точка внутри URI ломает путь, внутри подписи — грязнит подчёркивание.

Guardrails: не отправляй исходники диаграмм проекта во внешние рендер-сервисы; не линкуй временные (/tmp) файлы в документацию.
