# Создание навыка (SKILL)

Инструкция по созданию навыков для ИИ-агентов.

SKILL (навык) — это переносимый модуль (инструкции + скрипты), позволяющий агенту автономно выполнять конкретные задачи: работать с API, анализировать файлы и выполнять другие специфические действия. Это стандарт структурирования опыта, который агент загружает по мере необходимости.

## Стандарты и источники

Руководство следует официальному стандарту навыков агентов. При расхождениях источник истины — внешние стандарты, а не этот документ:

- [Спецификация навыков агентов](https://agentskills.io/specification) — формат навыка: структура каталога, заголовок с метаданными, проверка.
- [Использование скриптов в навыках](https://agentskills.io/skill-creation/using-scripts) — правило путей к скриптам относительно каталога навыка.
- [Рекомендации](https://agentskills.io/skill-creation/best-practices) — правила написания навыков.
- [anthropics/skills](https://github.com/anthropics/skills) — официальный репозиторий примеров (PDF, DOCX, веб-приложения для тестирования и др.).

Клиенты Pi, Claude Code и Codex реализуют этот стандарт.

## Структура

```
skill-name/
├── SKILL.md          # Обязательный файл: основная инструкция
├── scripts/          # Опционально — исполняемые скрипты
├── references/       # Опционально — справочные материалы
└── assets/           # Опционально — шаблоны, примеры файлов
```

## SKILL.md

### Заголовок YAML с метаданными (обязательно)

```yaml
---
name: skill-name
description: Что делает навык (кратко).
---
```

**Требования:**
- `name`: kebab-case, только строчные, без пробелов
- `description`: краткое описание функции навыка (до 1024 символов)
- Без XML-тегов (`< >`)

### Тело SKILL.md

`````
# Название навыка

## Когда использовать

- Ситуация 1
- Ситуация 2

## Как использовать

**Шаг 1:** Название шага

```bash
    command [опции] [аргументы]
```

Опции:

| Опция | Описание | Значения | По умолчанию |
|-------|----------|----------|--------------|
| --param | Описание | val1, val2 | val1 |

Примеры:

```bash
    command --param=val1
    command --param=val2 arg
```

**Шаг 2:** Название шага

    another-command [опции]

## Результат

Файл: `path/to/output.csv`

Поля:

| Поле | Описание |
|------|----------|
| field | Описание поля |
`````

## Разделы

| Раздел                 | Описание                                     |
|------------------------|----------------------------------------------|
| **Когда использовать** | Контекст применения                          |
| **Как использовать**   | Шаги с командами, опциями, примерами         |
| **Результат**          | Описание того что и где получим в результате |

## Шаги

Каждый шаг содержит:

1. **Инструкция шага** — описание того что нужно сделать агенту
2. **Команда** (опционально) — синтаксис вызова 
3. **Опции** (опционально) — таблица с параметрами
4. **Результат шага** (опционально) — таблица с параметрами
5. **Примеры** (опционально) — конкретные вызовы

`````
**Шаг 1:** Название
```
    command [опции]
```
Опции:

| Опция | Описание | Значения | По умолчанию |
|-------|----------|----------|--------------|
| --sort | Поле сортировки | visits, date | visits |
| --limit | Лимит записей | число | все |

Примеры:

```bash
    command --sort=date --limit=10
    command --limit=20
```
`````

## Скрипты и пути

Правила обязательны для каждого навыка со скриптами. Цель — переносимость: `SKILL.md` работает в клиенте, поддерживающем Agent Skills, и при любом месте установки без правок. При сбое запуска скрипта (`exit 127`, файл не найден) исправляют резолв или сам скрипт — форму команды в `SKILL.md` не меняют.

1. **Форма команды — только стандартная относительная.** Скрипт в `SKILL.md` вызывается формой `scripts/foo.sh` — путь относительно каталога навыка (каталога с `SKILL.md`). Пути от корня проекта и абсолютные пути в командах `SKILL.md` запрещены.
2. **Резолв пути — контракт раннера, не `SKILL.md`.** Стандарт Agent Skills требует относительные пути и автоматический резолв относительно каталога навыка (родителя `SKILL.md`), но не предписывает конкретный механизм. Механизм — контракт раннера (программы, запускающей агента): поддерживаемые раннеры pi, Claude Code и Codex вставляют в системный промпт правило «относительный путь в файле навыка резолвится относительно каталога навыка» и передают агенту абсолютный `<location>` каждого навыка. Сбой резолва — сбой контракта раннера: менять форму команды в `SKILL.md` из-за сбоя резолва запрещено.
3. **Комментарий-якорь в блоке кода с командой запуска.** Подстраховка от буквального копирования команды агентом: однострочный комментарий в первой строке каждого блока кода (code block) с командой запуска скрипта навыка — «Запускай из каталога скилла (каталог с этим SKILL.md)». Для неисполняемых примеров (вывод, разметка без запуска) комментарий не требуется. Образец — встроенные навыки Codex (`plugin-creator`: «Run from the skill root»); наш аналог — `become-role/SKILL.md`.
4. **Скрипт самонастраивающийся.** Скрипт не зависит от текущего рабочего каталога (`cwd`) вызывающего и сам определяет собственный каталог: Bash-скрипты — через `BASH_SOURCE`, скрипты на других языках (Python, JavaScript) — эквивалентными средствами языка. Корень host-проекта (проекта, установившего навык) скрипт восстанавливает по логическому пути — только если он нужен скрипту. Логический путь (`pwd -L`) сохраняет установленный `.agents/skills/<skill>` даже тогда, когда агент перешёл в каталог навыка по симлинку. Образец — `become-role/scripts/become-role.sh`.
5. **Тесты покрывают оба контекста запуска.** Запуск по абсолютному пути из произвольного `cwd` и запуск из каталога навыка — оба сценария зелёные.
6. **Разделение форм: `SKILL.md` и документы проекта.** `SKILL.md` — переносимая относительная форма; документы host-проекта (README, `cli.md`, `troubleshooting.md`) — установленный путь `.agents/skills/<skill>/scripts/...`.

## Принципы

1. **`description` краткий** — только что делает
2. **Структура** — когда → как → результат
3. **Шаги** — инструкция + команда + опции + примеры
4. **Результат** — описание + что и где получим

## Пример

```yaml
---
name: yandex-metrika-search
description: Поисковые фразы из Яндекс.Метрики для SEO-анализа
---
```

`````
# Поиск в Яндекс.Метрике

## Когда использовать

- Анализ поискового трафика
- Поиск популярных запросов
- Определение фраз с высокими отказами

## Как использовать

```bash
    php metrika.php [опции] [дата_от] [дата_до]
```

Параметры:

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| дата_от | Начало периода (YYYY-MM-DD) | 30 дней назад |
| дата_до | Конец периода (YYYY-MM-DD) | сегодня |

Опции:

| Опция | Сокращение | Описание | Значения | По умолчанию |
|-------|------------|----------|----------|--------------|
| --site | | Имя сайта | имя сайта | default_counter |
| --sort | -s | Поле сортировки | visits, bounce_rate, page_depth | visits |
| --order | -o | Направление | asc, desc | desc |
| --limit | -l | Лимит записей | число | все |

Примеры:

```bash
    # Топ-10 фраз
    php metrika.php --limit 10

    # Фразы с высоким отказом
    php metrika.php -s bounce_rate -l 20

    # За период
    php metrika.php -l 10 2025-01-01 2025-01-31
```

## Результат

Файл: `yandex_metrika_reports/YYYY-MM-DD/yandex_metrika_phrases.csv`

Поля:

| Поле | Описание |
|------|----------|
| phrase | Поисковая фраза |
| visits | Визиты |
| visitors | Посетители |
| bounce_rate | Процент отказов |
| page_depth | Глубина просмотра |
| avg_duration | Среднее время на сайте (сек) |
`````
