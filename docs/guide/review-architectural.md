# Архитектурное ревью

Архитектурное ревью отвечает на вопрос «соответствует ли решение проекту?». Ответственность — строка архитектурного ревью [матрицы RACI](../agents/raci-matrix.md).

## Необходимость архитектурного ревью

Архитектурное ревью обязательно для задач, у которых сложность (`complexity`) C2+ или при любом из признаков по фактическому набору изменений:

1. Новый, удаляемый или перемещаемый модуль; смена владельца бизнес-логики.
2. Новые или изменённые зависимости между слоями и модулями.
3. Изменение контракта другого модуля или внешнего потребителя (обработчик Application, DTO, CLI, конфигурация, событие, сохраняемый формат, семантика ошибки).
4. Изменения `Kernel`, модульной регистрации, `config/`, `depfile.yaml`, архитектурно значимых зависимостей `composer.json`.
5. Новый архитектурный паттерн или отступление от Конвенции/ADR.

Запись «нужно ли архитектурное ревью: да/нет» + основание обязательна в задании ревьюверу; отсутствие записи означает, что необходимость ревью не определена. Решение пересматривается по каждой дельте до приёмки; сомнение — в пользу архитектурного ревью. C0–C1 без признаков — одно комбинированное ревью (архитектурное не проводится).

## Ослабления проверок качества

Ослабления проверок качества (exclude-списки, suppress-метки — `@psalm-suppress`, `@phpstan-ignore*`, `@SuppressWarnings(PHPMD.*)`, оператор `@`, рост baseline, смягчение thresholds) допустимы только с техдолг-задачей. Правила подавлений PHPMD — [подавления PHPMD](../conventions/ops/phpmd-suppressions-guidelines.md).

## Дельта метрик качества

`vendor/bin/coding-standard-metrics-review --base=<target>` формирует дельту (CC/WMC, LCOM4/Ca/Ce, покрытие, churn) в `var/metrics-review/`: подсвечивает, где пахнет код и куда смотреть; замечание — по решению ревьювера. Правила интерпретации — [метрики качества](../conventions/ops/quality-metrics.md).

## Чек-лист

- [ ] Применимые Конвенции, ADR и архитектурные правила прочитаны
- [ ] Логика и зависимости в границах своих слоёв и модулей
- [ ] Доменное поведение на своём месте (DDD)
- [ ] Контракты и обратная совместимость не сломаны
- [ ] Ослабления проверок качества (exclude, suppress, baseline) сопровождены техдолгом и задачей
- [ ] Дельта метрик изучена
- [ ] DI и конфигурация соответствуют ADR-012 (при затрагивании)
- [ ] Надёжность: повторы, бюджеты, транзакции согласованы (при затрагивании)
- [ ] Внешние зависимости в допустимом слое (при затрагивании)
- [ ] Секреты не протекают через границы (при затрагивании)
- [ ] Новое архитектурное решение записано в ADR (при появлении)
