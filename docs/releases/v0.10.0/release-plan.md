## Совместимость и установка

- Линия `0.x`: публичный API нестабилен; несовместимых изменений в составе нет.
- Новые компоненты (`Layout`, `PharCache`) внутренние для ядра; env-процессоры используют префикс `task_orchestrator_layout.*` со значениями по умолчанию, сохраняющими прежнее поведение.
- `config/chains.yaml` — расклад владельца; проекты-потребители используют собственный конфиг цепей.
- Миграции и новые обязательные переменные окружения не нужны; навыки и SDLC поставляются в пакете как раньше.

## Проверки перед тегом

Выполнять после слияния подготовительного запроса на точной принятой вершине `main`, а не на этой ветке:

```bash
git switch main
git pull --ff-only origin main
git status --short
git rev-parse HEAD
composer validate --strict
make check
make phar-e2e
```

На момент подготовки на ветке подготовки выполнен `make check`; `composer validate --strict` и `make phar-e2e` обязательны на принятом `main` и не заменяются документными проверками.

## Тег, публикация и проверки после тега

1. После зелёных проверок и явного разрешения пользователя создать неизменяемый аннотированный тег на проверенной вершине `main`:

   ```bash
   git tag -a v0.10.0 -m "chore(release): v0.10.0"
   ```

2. Отправить только этот тег по утверждённому HTTPS-рецепту GitHub App. GitHub Release создаётся workflow `Release Phar` автоматически.
3. Дождаться успешного `Release Phar`; проверить опубликованный asset:

   ```bash
   gh run list --workflow 'Release Phar' --event push --limit 1
   gh release view v0.10.0 --json tagName,assets
   ```

4. Не изменять и не перемещать тег. При ошибке — отдельный patch из `main` через Pull Request.

## Риски

- Между подготовкой и тегированием `main` может измениться; состав, проверки и тег повторно привязываются к фактически принятой вершине.
- Runtime-резолвинг путей меняет поведение кеширования контейнера: поведение покрыто тестами #440/#448 и `make phar-e2e`; при проблеме у потребителей — patch по разделу «Действия при проблеме».
- Предрелизная проверка `make phar-e2e` вскрыла устаревший E2E-асерт (шаг «≥2 корня» противоречил FR-4); цель — только локальная, в CI отсутствует; асерт синхронизирован (`TASK-fix-phar-e2e-cache-root-auto-clean`).
- Очистка PHAR-кеш-корней затрагивает системный временный каталог; защита — маркер владения и `flock`-арбитр (#443), предупреждение не меняет exit code.

## Действия при проблеме

- Откат не используется; опубликованный тег не изменяется; исправление выпускается отдельной patch-версией.
