# План релиза v0.15.1

## Метаданные

- Тег: `v0.15.1`.
- Тип: `patch` — только `docs` и `chore(deps)`, ни `feat`, ни `fix`, ни `BREAKING CHANGE` в диапазоне `v0.15.0..main` нет.
- База: актуальная `main` после слияния #482 (`fb0dbfb6`).
- Ветка: `release/0.15.1`.
- PR подготовки: создаётся из этой ветки.
- Ответственный: владелец проекта.
- Плановая дата: 2026-11-12.

## Состав

- #481 — `docs(retrospective)`: обратная связь постановщику в скилле ретроспективы (Шаг 2 «Анализ ролей и постановки», обязательный раздел в файле ретро, блок в отчёте Шага 8, шаблон, README, описание навыка в роли тимлида). Задача в `todo/` не оформлялась — правка процесса по прямому запросу владельца.
- #482 — `chore(deps)`: `prikotov/todo-md` `v0.3.0` → `v0.4.0` (dev-зависимость, `require-dev`; ключи `--model`/`--thinking` в CLI `create`/`start`).
- Подготовительный PR с `CHANGELOG.md`, этим планом и релизной задачей `TASK-release-v0-15-1-preparation`.

## Риски и несовместимость

- Несовместимых изменений нет: правки документации скилла и dev-зависимости; PHP-код `src/` не затронут.
- Поведение потребителей ретроспективы меняется только в сторону добавления обязательного раздела «Обратная связь постановщику» в файлы ретро.
- Обновление todo-md затрагивает только CLI-инструменты разработки (валидация, создание задач); формат задач не изменился.
- Миграции данных и переменные окружения не требуются.
- Известное отклонение: локальный `make phpmd` падает на ранее существовавших замечаниях `ExcessiveClassLength` (`src/Kernel.php`, `YamlChainLoaderService.php`) — файлы релизом не затронуты, замечания присутствуют начиная с v0.14.0; CI репозитория зелёный.

## Порядок публикации

1. Слить подготовительный PR в `main` после одобрения владельца и подтверждения слияния.
2. Проверить совпадение содержимого merge commit и одобренной вершины `release/0.15.1`.
3. Выполнить проверки и `make phar-e2e` на проверенном merge commit.
4. Создать и опубликовать только тег `v0.15.1` на проверенном merge commit.
5. Дождаться workflow `Release Phar` и проверить GitHub Release.

## Проверки перед публикацией

```bash
composer validate --strict
vendor/bin/phpunit
vendor/bin/psalm
vendor/bin/deptrac analyse --config-file=depfile.yaml --no-progress
make phar-smoke PHAR_EXPECTED_VERSION=dev
make phar-e2e
```

Ожидаемый результат: код завершения `0`, рабочее дерево чистое.

## Проверки после публикации

- `gh release view v0.15.1 --json tagName,assets` — релиз содержит PHAR-asset.
- Workflow `Release Phar` для тега успешен.
- `git rev-list -n 1 v0.15.1` возвращает проверенный merge commit.

## Действия при проблеме

- Откат и перемещение тега не используются.
- Проблема исправляется отдельным patch release (`release/0.15.2`) через PR по сценарию hotfix.
- Ответственный: владелец проекта; координация — в задаче на исправление.
