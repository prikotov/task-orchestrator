# План релиза v0.5.1

## Метаданные

- Тег релиза: `v0.5.1`
- База релиза: `main`
- Последний опубликованный тег: `v0.5.0`
- Ответственный: Тимлид Алекс (pi)
- Плановая дата публикации: 2026-08-23

## Состав

- Исправлена пакетная установка через Composer: `become-role` вновь определяет корень проекта-потребителя и загружает его профиль роли (запрос [#371](https://github.com/prikotov/task-orchestrator/pull/371), коммит слияния `72e4f85`).
- Кэш консольного приложения изолирован по версии пакета, поэтому разные версии не используют общий кэш.
- Публичный контракт вывода JSON/XML команды `agent:role-skills` не изменён.
- Установка `become-role` в PHAR не менялась.
- Вне состава: миграции, изменения кода после подготовительного запроса релиза и любые изменения, не входящие в запрос #371.

## Риски

- Основной риск: пакетная установка должна искать профиль роли от корня проекта-потребителя; неверный путь снова лишит потребителя профиля роли.
- Наличие миграций данных: нет.
- Порядок применения миграций: не требуется.
- Риск окна несовместимости: низкий. Версионирование кэша создаст новый локальный кэш, но не изменит внешний контракт.
- Обратная совместимость: публичный контракт вывода JSON/XML команды `agent:role-skills` сохранён; поддержка `become-role` в PHAR не меняется.

## Порядок публикации

1. Убедиться, что подготовительный запрос с этими артефактами слит в `main` и его обязательные проверки зелёные.
2. Убедиться, что `main` содержит только согласованный состав релиза: запрос #371 и артефакты `v0.5.1`.
3. Создать тег `v0.5.1` на вершине `main` и отправить его через GitHub App.
4. Дождаться сценария `Release Phar`: он автоматически создаёт GitHub Release и загружает файл `task-orchestrator.phar`.
5. Проверить автоматически созданный GitHub Release; при необходимости обновить его заметки о запросе #371 и PHAR-артефакте через `gh release edit`, не создавая выпуск повторно.
6. Проверить опубликованный PHAR командой `php task-orchestrator.phar list`.

## Проверки перед публикацией

- [ ] Подготовительный запрос слит в `main`; непрерывная интеграция зелёная.
- [ ] `make check` успешно выполнен на вершине `main`.
- [ ] `PHAR_EXPECTED_VERSION=dev make phar-smoke` и `make composer-host-smoke` успешно выполнены до публикации тега.
- [ ] Тег `v0.5.1` отсутствует до публикации.
- [ ] В `main` присутствуют запись `CHANGELOG.md`, план `v0.5.1` и завершённая задача подготовки release PR.

## Проверки после публикации

- [ ] Выпуск GitHub содержит тег `v0.5.1` и `task-orchestrator.phar`.
- [ ] `git describe --tags` на `main` показывает `v0.5.1`.
- [ ] PHAR запускается: `php task-orchestrator.phar list`.
- [ ] Пакетная установка загружает профиль роли от корня проекта-потребителя; версии пакета не используют общий кэш.
- [ ] Публичный вывод JSON/XML команды `agent:role-skills` остаётся совместимым.

## Действия при проблеме после релиза

- Откат неизменяемого тега не используется.
- Стратегия исправления: срочное исправление от тега `v0.5.1` в ветку `hotfix/0.5.2-<short-description>` с последующим запросом на слияние в `main` и выпуском исправления `v0.5.2`.
- Ответственный инженер: Тимлид Алекс (pi).
- Канал коммуникации и фиксации: `todo/` и запрос GitHub.
