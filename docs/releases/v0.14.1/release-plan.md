# План релиза v0.14.1

## Метаданные

- Тег: `v0.14.1`.
- Тип: `patch` — с `v0.14.0` только `docs`/`chore`-коммиты, `feat`/`fix` нет; несовместимых изменений нет.
- База: актуальная `main` после слияния #476 (`1d2b4533`).
- Ветка: `release/0.14.1`.
- PR подготовки: создаётся из этой ветки.
- Ответственный: владелец проекта.
- Плановая дата: 2026-11-10.

## Состав

- #476 — актуализация скилла `pi-native-rendering` под pi 1.5.1: +4 рисуемых типа диаграмм (`pie`, `mindmap`, `timeline`, `gitGraph`), запрет перенесён на нерисуемые, блок «Кликабельность ссылок» (OSC 8); задача `TASK-docs-pi-native-rendering-pi-1-5-1`.
- #471, #474, #475 — research-постановки (память агента, агентное ревью кода, гид Google по agent skills, feasibility dsh, X-пост dsh).
- #473 — обновление выводов ZCode (bundled headless CLI, desktop v3.17.2).
- Подготовительный PR с `CHANGELOG.md`, этим планом и релизной задачей.

## Риски и несовместимость

- Изменения только в документации (`docs/**`, `todo/**`, `CHANGELOG.md`); код, конфигурации и скрипты не затронуты.
- PHAR меняется содержимым скилла (`docs/agents/skills/pi-native-rendering/SKILL.md`) без кода; размер практически не меняется.
- Миграции данных и новые обязательные переменные окружения не требуются.
- Несовместимые изменения отсутствуют.

## Порядок публикации

1. Слить подготовительный PR в `main` после подтверждения владельца.
2. Проверить совпадение содержимого merge commit и одобренной вершины `release/0.14.1`.
3. Выполнить проверки и `make phar-e2e` на проверенном merge commit.
4. Создать и опубликовать только тег `v0.14.1` на проверенном merge commit.
5. Дождаться workflow `Release Phar` и проверить GitHub Release.

## Проверки перед публикацией

```bash
composer validate --strict
vendor/bin/phpunit
vendor/bin/psalm
vendor/bin/deptrac analyse --config-file=depfile.yaml --no-progress
make phar-smoke PHAR_EXPECTED_VERSION=dev
make phar-e2e
```

Ожидаемый результат: код завершения `0`, рабочее дерево чистое.

## Проверки после публикации

- `gh release view v0.14.1 --json tagName,assets` — релиз содержит PHAR-asset.
- Workflow `Release Phar` для тега успешен.
- `git rev-list -n 1 v0.14.1` возвращает проверенный merge commit.

## Действия при проблеме

- Откат и перемещение тега не используются.
- Проблема исправляется отдельным patch release через PR.
- Ответственный: владелец проекта; координация — в задаче на исправление.
