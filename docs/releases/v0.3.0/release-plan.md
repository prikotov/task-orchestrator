# План релиза v0.3.0

## Метаданные

- Тег релиза: `v0.3.0`
- База релиза: `main`
- Последний опубликованный тег: `v0.2.3`
- Ответственный: Тимлид Алекс (codex-cli)
- Плановая дата публикации: 2026-08-20

## Состав

- Локалезависимое разрешение role file (файла роли) для `become-role` через `APP_LOCALE` (PR #318–#320).
- Исправления GitHub App identity (идентичности GitHub App), Codex/Pi runner lifecycle (жизненного цикла движков) и обработки JSONL (PR #323, #352, #354, #357).
- `run-subagent` читает профиль роли потребляющего Composer-проекта, а не каталог пакета (PR #359).
- `main` синхронизирован с историей выпусков `v0.2.0`–`v0.2.3` (PR #360).
- Вне состава: новые изменения после слияния release preparation PR (PR подготовки релиза).

## Риски

- Основной риск: новая логика разрешения профиля роли влияет на делегирование сабагентов в Composer-установках; покрыта интеграционным тестом и Composer-host smoke.
- Наличие миграций данных: нет.
- Порядок применения миграций: не требуется.
- Риск окна несовместимости: отсутствует.
- Обратная совместимость: запуск `watch-subagent.sh` из checkout (рабочей копии) пакета сохраняет прежнее поведение.

## Порядок публикации

1. Убедиться, что PR подготовки слит в `main`, `make check` и CI зелёные.
2. Создать tag `v0.3.0` на вершине `main` и отправить его через GitHub App.
3. Дождаться workflow `Release Phar` и проверить asset (артефакт) `task-orchestrator.phar`.
4. Создать GitHub Release с заметками о составе и проверках.
5. Обновить потребляющий TasK до `prikotov/task-orchestrator:^0.3.0` и выполнить его проверки.

## Проверки перед публикацией

- [x] `make check` успешно выполнён.
- [ ] CI PR подготовки зелёный, включая Composer-host smoke и PHP 8.4.1 PHAR smoke.
- [ ] Tag `v0.3.0` отсутствует до публикации.
- [ ] В `main` присутствуют записи `CHANGELOG.md` и планы v0.2.0–v0.2.3.

## Проверки после публикации

- GitHub Release содержит tag `v0.3.0` и `task-orchestrator.phar`.
- `git describe --tags` на `main` показывает `v0.3.0`.
- TasK после обновления зависимости использует профиль роли из собственного `config/chains.yaml`.

## Действия при проблеме после релиза

- Откат immutable tag не используется.
- Стратегия исправления: `hotfix/0.3.1-<short-description>` от `v0.3.0` с последующим PR в `main` и patch release.
- Ответственный инженер: Тимлид Алекс (codex-cli).
- Канал коммуникации и фиксации: `todo/` и GitHub Pull Request.

## Заметки

- Выпуск из `main` закрепляет политику: опубликованная история не должна оставаться только в отдельной release-ветке.
