# План релиза v0.5.0

## Метаданные

- Тег релиза: `v0.5.0`
- База релиза: `main`
- Последний опубликованный тег: `v0.4.1`
- Ответственный: Тимлид Алекс (pi)
- Плановая дата публикации: 2026-08-23

## Состав

- Сохранение нативных сессий агентов (PR #369, задача `TASK-feat-persist-agent-sessions`): Pi runner и `watch-subagent.sh` больше не используют `--no-session`; активные профили ролей больше не используют `--no-session` и `--ephemeral`.
- Документация и проверки (PR #369): обновлены описание стандартной команды Pi, руководства по ролям и цепочкам, интеграционные и модульные тесты.
- Вне состава: изменения, появившиеся в `main` после release preparation PR.

## Риски

- Основной риск: нативные журналы сессий могут содержать промпты и ответы; они сохраняются локально в стандартных каталогах Pi и Codex и не изменяют внешние интеграции.
- Наличие миграций данных: нет.
- Порядок применения миграций: не требуется.
- Риск окна несовместимости: низкий. Изменено поведение хранения локальных журналов, CLI-контракт запуска не менялся.
- Обратная совместимость: команды явно содержащие `--no-session` или `--ephemeral` продолжают задавать отключённый режим; стандартные команды теперь сохраняют сессии.

## Порядок публикации

1. Убедиться, что release preparation PR слит в `main`, `make check` и CI зелёные.
2. Создать тег `v0.5.0` на merge-коммите release preparation PR и отправить его через GitHub App.
3. Дождаться workflow `Release Phar` и проверить asset `task-orchestrator.phar`.
4. Создать GitHub Release с заметками о составе и проверках.
5. Проверить запуск опубликованного PHAR командой `php task-orchestrator.phar list`.

## Проверки перед публикацией

- [x] `make check` успешно выполнен.
- [x] `PHAR_EXPECTED_VERSION=dev make phar-smoke` и `make composer-host-smoke` успешно выполнены до публикации тега.
- [ ] CI release preparation PR зелёный, включая Composer-host smoke и PHP 8.4.1 PHAR smoke.
- [x] Тег `v0.5.0` отсутствует до публикации.
- [ ] В `main` присутствуют запись `CHANGELOG.md`, план `v0.5.0` и завершённая задача релиза.

## Проверки после публикации

- [ ] GitHub Release содержит тег `v0.5.0` и `task-orchestrator.phar`.
- [ ] `git describe --tags` на `main` показывает `v0.5.0`.
- [ ] PHAR запускается: `php task-orchestrator.phar list`.
- [ ] Новый запуск Pi или Codex создаёт нативный журнал, доступный collector dashboard.

## Действия при проблеме после релиза

- Откат immutable tag не используется.
- Стратегия исправления: hotfix от тега `v0.5.0` в ветку `hotfix/0.5.1-<short-description>` с последующим PR в `main` и patch release `v0.5.1`.
- Ответственный инженер: Тимлид Алекс (pi).
- Канал коммуникации и фиксации: `todo/` и GitHub Pull Request.
