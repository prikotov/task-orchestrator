# План релиза v0.11.0

## Метаданные

- Тег релиза: `v0.11.0`.
- Тип повышения версии: `minor` — новая совместимая функциональность в линии `0.y`.
- База: актуальная `main` после слияния #458.
- Рабочая ветка: `release/0.11.0`.
- PR подготовки: будет указан в `TASK-release-v0-11-0-preparation`.
- Ответственный: владелец проекта.
- Плановая дата: 2026-11-05.

## Состав

- #457 — разделение базового системного промпта и ролевой инструкции.
- #458 — именованные командные профили и выбор профиля по сложности задачи в `watch-subagent.sh`.
- Задачи `TASK-config-subagent-base-prompt` и `TASK-feat-complexity-based-role-commands`.
- Подготовительный PR с `CHANGELOG.md`, этим планом и релизной задачей.

## Риски

- Выбор профиля зависит от корректности `complexity`; явный `--complexity` позволяет переопределить значение.
- Конфигурация сохраняет одиночную `command`; миграции данных и новые обязательные env не требуются.
- Несовместимых изменений нет.

## Порядок deploy

1. Слить подготовительный PR в `main`.
2. Проверить совпадение содержимого merge commit и одобренной вершины `release/0.11.0`.
3. Выполнить проверки и `make phar-e2e` на проверяемом merge commit.
4. Создать и опубликовать только тег `v0.11.0` на проверенном merge commit.
5. Дождаться workflow `Release Phar` и проверить GitHub Release.

## План проверок перед выкладкой

```bash
composer validate --strict
vendor/bin/phpunit
vendor/bin/psalm
vendor/bin/deptrac analyse --config-file=depfile.yaml --no-progress
make phar-e2e
```

Ожидаемый результат: все команды завершаются с кодом `0`, рабочее дерево чистое.

## План проверок после выкладки

- `gh release view v0.11.0 --json tagName,assets` — существует релиз с PHAR-asset.
- Workflow `Release Phar` для тега успешен.
- В логах публикации отсутствуют ошибки; очереди и workers проектом не используются.
- `git rev-list -n 1 v0.11.0` возвращает проверенный merge commit.

## Действия при проблеме после релиза

- Откат и перемещение тега не используются.
- Проблема исправляется отдельным patch release через PR.
- Ответственный: владелец проекта; координация — в задаче на исправление.
