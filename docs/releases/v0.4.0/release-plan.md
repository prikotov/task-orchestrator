# План релиза v0.4.0

## Метаданные

- Тег релиза: `v0.4.0`
- База релиза: `main`
- Последний опубликованный тег: `v0.3.1`
- Ответственный: Тимлид Алекс (pi)
- Плановая дата публикации: 2026-08-21

## Состав

- Use Case шины (PR #364, задача TASK-refactor-usecase-bus-dispatch): компоненты `src/Component/CommandBus` и `src/Component/QueryBus` (интерфейсы, реализации на PSR-11 локаторе, `UseCaseBusCompilerPass` с автоподхватом хендлеров по рефлексии); все 16 прямых вызовов хендлеров в 6 CLI-командах и 4 Integration-сервисах переведены на `execute()`/`query()`; unit + integration тесты; `docs/guide/architecture.md` дополнен.
- Обновление зависимостей `prikotov/*` (PR #364): coding-standard 0.29.3 → 0.30.0 (constraint `^0.30.0`, подключены PHPStan-правила пакета), todo-md 0.0.10 → 0.0.11; git-workflow 0.3.1 без изменений.
- Ретро-документация (PR #365): ретро 2026-08-21 о цикле снятия апрува done-коммитом + запись в реестре RETRO-ROADMAP.
- Вне состава: изменения, появившиеся в `main` после release preparation PR (PR подготовки релиза).

## Риски

- Основной риск: новая проводка контейнера (`UseCaseBusCompilerPass`) затрагивает сборку сервисов во всех контекстах (dev/PHAR/host) — покрыта интеграционным тестом проводки в реальном контейнере, Composer-host smoke и Phar smoke в CI зелёные на PR #364.
- Наличие миграций данных: нет.
- Порядок применения миграций: не требуется.
- Риск окна несовместимости: отсутствует. Внешний контракт CLI не менялся; для потребителей, вызывавших хендлеры напрямую, прежний способ остаётся рабочим (хендлеры — по-прежнему сервисы), но новый канонический путь — шины.
- Обратная совместимость: возвращаемые типы хендлеров и сигнатуры сообщений не менялись; `RunAgentQueryHandler` (не-invokable) вне диспетчеризации.

## Порядок публикации

1. Убедиться, что PR подготовки слит в `main`, `make check` и CI зелёные.
2. Создать tag `v0.4.0` на вершине `main` и отправить его через GitHub App.
3. Дождаться workflow `Release Phar` и проверить asset (артефакт) `task-orchestrator.phar`.
4. Создать/дополнить GitHub Release с заметками о составе и проверках.
5. Обновить потребляющие проекты (TasK/codexcli) до `prikotov/task-orchestrator:^0.4.0` и проверить работу CLI и `become-role`.

## Проверки перед публикацией

- [x] `make check` успешно выполнён.
- [ ] CI PR подготовки зелёный, включая Composer-host smoke и PHP 8.4.1 PHAR smoke.
- [ ] Tag `v0.4.0` отсутствует до публикации.
- [ ] В `main` присутствует запись `CHANGELOG.md` и план v0.3.1.

## Проверки после публикации

- GitHub Release содержит tag `v0.4.0` и `task-orchestrator.phar`.
- `git describe --tags` на `main` показывает `v0.4.0`.
- В host-проекте после `composer update prikotov/task-orchestrator` шины резолвятся (CLI-команды выполняются без ошибок контейнера).

## Действия при проблеме после релиза

- Откат immutable tag не используется.
- Стратегия исправления: `hotfix/0.4.1-<short-description>` от `v0.4.0` с последующим PR в `main` и patch release.
- Ответственный инженер: Тимлид Алекс (pi).
- Канал коммуникации и фиксации: `todo/` и GitHub Pull Request.

## Заметки

- Minor (а не patch): новая функциональность — публичные компоненты шин и компилятор-пас.
- При обновлении host-проектов: `var/cache` пересобирается автоматически; при локальных экспериментах между ветками чистить вручную (`rm -rf var/cache`) — иначе возможен `ClassNotFoundError` от закешированного контейнера (случай из релизной сессии v0.3.1).
