# План релиза v0.8.1

## Метаданные

- Тег релиза: `v0.8.1`
- Тип повышения версии: `patch`
- Обоснование выбранной версии: docs-only изменения (конвенция скиллов и `SKILL.md` поставляются пакетом, публичный runtime-контракт не меняется) — стабилизация текущей линии `0.8.x`
- База релиза: актуальная `main` (`d390586`) по `docs/releases/RELEASE-POLICY.md`
- Рабочая ветка подготовки: `task/release-v0-8-1`
- PR подготовки релиза: см. поле `pr` задачи `TASK-release-v0-8-1-preparation`
- Последний опубликованный тег: `v0.8.0`
- Ответственный: Тимлид Алекс (pi)
- Плановая дата публикации: 2026-09-17

## Состав

- [#396](https://github.com/prikotov/task-orchestrator/pull/396) — плейсхолдер-форма команды запуска скриптов скилла (`<skill-dir>/scripts/…`): конвенция `SKILL-CREATION.md` (п.1–3, п.6, чеклист), `become-role/SKILL.md`, README скилла, запись реестра ретро (`exit 127` → escalated).

## Совместимость и известные ограничения

- Код и тесты не меняются; CLI-контракт `0.8.0` сохранён.
- Эффект в host-проектах — после обновления зависимости: агенты больше не копируют `bash scripts/…` дословно (плейсхолдер требует подстановки каталога из `<location>`).
- Кандидат отдельной задачей: перевод `run-subagent/SKILL.md` на плейсхолдер-форму (5 блоков с относительной формой).
- Миграции и новые переменные окружения отсутствуют.

## Порядок публикации

1. Слить подготовительный PR в `main` после успешного CI, ревью и явного подтверждения merge.
2. Создать и отправить тег `v0.8.1` на коммит слияния.
3. Дождаться workflow `Release Phar` (GitHub Release + `task-orchestrator.phar`).
4. Проверить опубликованный PHAR и описание выпуска.

## Проверки перед публикацией

- `composer validate --strict`
- CI подготовительного PR успешен (docs-only: `make check` пропущен по исключению, прогнаны `md-links`/`validate-todo`/`validate-language`/`validate-roles` в #396)

## Проверки после публикации

- GitHub Release `v0.8.1` содержит непустой `task-orchestrator.phar`.
- `php task-orchestrator.phar --version` сообщает `0.8.1`.
- В свежем host-проекте `agent:init` + `become-role.sh <role>` работают как в `0.8.0`.

## Действия при проблеме после релиза

- Откат и изменение опубликованного тега не используются; исправление — patch-релиз `v0.8.2`.
