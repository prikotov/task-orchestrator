# План релиза v0.7.0

## Метаданные

- Тег релиза: `v0.7.0`
- Тип повышения версии: `minor`
- Обоснование выбранной версии: добавлена новая совместимая возможность установки `become-role` из PHAR; для серии `0.x` новая функциональность повышает `minor`
- База релиза: актуальная `main` (`4fa1afb`) по `docs/releases/RELEASE-POLICY.md`
- Рабочая ветка подготовки: `task/release-v0-7-0`
- PR подготовки релиза: [#392](https://github.com/prikotov/task-orchestrator/pull/392)
- Последний опубликованный тег: `v0.6.0`
- Ответственный: Технический писатель Гермиона (pi)
- Плановая дата публикации: 2026-09-16

## Состав

- [#387](https://github.com/prikotov/task-orchestrator/pull/387) — полноценная установка управляемой копии skill `become-role` командой `agent:init` из PHAR-дистрибутива, runtime-привязка `.phar-binding`, идемпотентность и `--force` для замены.
- [#390](https://github.com/prikotov/task-orchestrator/pull/390) — исправление ложного кода завершения `141` при вычислении сводки `run-subagent`.
- Исправлен путь скрипта `validate-md-links` в Composer-конфигурации.
- Усилены E2E-проверки PHAR-дистрибутива; production-safe `bin/phar-smoke` сокращён до сборки, версии и регистрации команд.
- Исследовательские и служебные изменения после `v0.6.0` не меняют публичный runtime-контракт.

## Совместимость и известные ограничения

- Публичные CLI-команды и существующий Composer-канал обратно совместимы.
- Установленный из PHAR `become-role` привязан к физическому пути архива. После перемещения или удаления PHAR требуется повторный `agent:init --force`.
- Известный дефект `TASK-fix-phar-runtime-layout-cache` остаётся в backlog: появившиеся после первой компиляции host-ресурсы могут потребовать очистки кеша, а старые PHAR cache roots автоматически не очищаются. PHAR остаётся secondary/best-effort каналом; основной Composer-канал не блокирован.
- Миграции данных и новые переменные окружения отсутствуют.

## Порядок публикации

1. Слить подготовительный PR в `main` после успешного CI, ревью и явного подтверждения merge.
2. Проверить, что коммит слияния совпадает по содержимому с одобренной веткой.
3. Выполнить проектные проверки на вершине `main`.
4. Создать и отправить тег `v0.7.0` на проверенный коммит слияния.
5. Дождаться workflow `Release Phar`, который создаст GitHub Release и загрузит `task-orchestrator.phar`.
6. Проверить опубликованный PHAR и описание выпуска.

## Проверки перед публикацией

- `composer validate --strict`
- `composer audit`
- `make check`
- `make composer-host-smoke`
- `PHAR_EXPECTED_VERSION=dev make phar-smoke`
- CI подготовительного PR успешен

## Проверки после публикации

- GitHub Release `v0.7.0` содержит непустой `task-orchestrator.phar`.
- `php task-orchestrator.phar --version` сообщает `0.7.0`.
- В пустом host-проекте `php task-orchestrator.phar agent:init` устанавливает `.agents/skills/become-role`, а повторный запуск идемпотентен.
- Установленный `become-role.sh` разрешает роль через опубликованный PHAR.

## Действия при проблеме после релиза

- Откат и изменение опубликованного тега не используются.
- Исправление выпускается patch-релизом `v0.7.1` по проектной политике.
- Координация: задача в `todo/` и GitHub PR.
