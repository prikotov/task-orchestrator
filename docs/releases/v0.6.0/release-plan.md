# План релиза v0.6.0

## Метаданные

- Тег релиза: `v0.6.0`
- Тип повышения версии: `minor`
- Обоснование выбранной версии: состав содержит несовместимое изменение конфигурации (breaking change) — [#380](https://github.com/prikotov/task-orchestrator/pull/380) заменяет контракт `APP_LOCALE` на `TASK_ORCHESTRATOR_LOCALE`. По принятой проектной SemVer-конвенции breaking change в серии `0.x` повышает `minor` (`0.5.x` → `0.6.0`), а не `patch`.
- База релиза: `main`. Проект выпускает релизы только из `main` по [RELEASE-POLICY.md](../RELEASE-POLICY.md); отдельная линия `release/x.y` для этого релиза не открывается.
- Последний опубликованный тег: `v0.5.3`
- Ответственный: Технический писатель Гермиона (pi)
- Плановая дата публикации: 2026-09-10

## Состав

- [#380](https://github.com/prikotov/task-orchestrator/pull/380) — отделение локали AI-ролей от host-проекта: новая переменная окружения `TASK_ORCHESTRATOR_LOCALE` (выбор файла роли, язык заголовков каталога skills), `APP_LOCALE` больше не является контрактом task-orchestrator; локаль Symfony-переводчика (`framework.default_locale`) стала независимой стандартной настройкой (`en`); исправлен баг устаревшего кеша (stale cache) — локаль не запекается в скомпилированный контейнер. Обновлены `.env.example`, `AGENTS.md`, `config/packages/translation.yaml`, `docs/guide/extension.md`; CLI-команды и сигнатуры PHP-контрактов не менялись (в `LocateRoleFileServiceInterface` обновлён только PHPDoc).
- [#381](https://github.com/prikotov/task-orchestrator/pull/381) — полное обновление зависимостей до устойчивых линий: ограничения (constraints) `require-dev` подняты на новые линии — `prikotov/coding-standard` `^0.33.0` (0.32 → 0.33), `phpunit/phpunit` `^13.3` (10.5 → 13.3), `deptrac/deptrac` `^4.7` (2.0 → 4.7); `composer.lock` обновлён целиком — runtime `symfony/*` выровнен на линию 8.1.x (ранее смесь 8.0.x и 8.1.0) в рамках действующего ограничения `^8.0`, PHPStan 2.1 → 2.2; точечная адаптация двух тестов под новые версии.
- [#382](https://github.com/prikotov/task-orchestrator/pull/382) — модернизация тестовых двойников (test doubles) PHPUnit под PHPUnit 13: набор тестов проходит без notices и deprecations PHPUnit; в `phpunit.xml.dist` включены защитные флаги `failOnPhpunitDeprecation` и `failOnPhpunitNotice`; в `bin/liveness-smoke` устаревшая опция `--do-not-cache-result` заменена на `--do-not-record-test-run-history`.
- Включённые задачи: [`todo/done/TASK-refactor-task-orchestrator-locale.todo.md`](../../../todo/done/TASK-refactor-task-orchestrator-locale.todo.md) (#380), [`todo/done/TASK-update-all-dependencies.todo.md`](../../../todo/done/TASK-update-all-dependencies.todo.md) (#381), [`todo/done/TASK-modernize-phpunit-test-doubles.todo.md`](../../../todo/done/TASK-modernize-phpunit-test-doubles.todo.md) (#382).
- Стабилизационная документационная правка релиза: `.env.example` точно разделяет поведение при пустой `TASK_ORCHESTRATOR_LOCALE` — порядок поиска role file `<role>.md` → `<role>.en.md` → `<role>.ru.md` → `<role>.zh.md` → первый найденный `<role>.*.md` и язык заголовков каталога skills по умолчанию `en` (без заявления безусловного дефолта `en` для role file).
- Вне состава релиза: любые изменения после подготовительного release PR (запрос на слияние артефактов релиза).

## Миграция окружения (обязательная)

Состав релиза не содержит миграций данных; мигрирует только переменная окружения host-проектов.

1. В окружении host-проекта (например, `.env.local` Composer-установки) **добавьте** `TASK_ORCHESTRATOR_LOCALE=ru`. `APP_LOCALE` больше не читается task-orchestrator: скрытый резервный переход (fallback) на неё отсутствует намеренно — без новой переменной role file выбирается без приоритета `.ru.md`, а заголовки каталога skills выводятся языком по умолчанию (`en`).
2. `APP_LOCALE` не удаляйте безусловно: task-orchestrator её больше не читает, но переменная может принадлежать самому host-приложению (стандартная настройка Symfony-приложения) или другим пакетам. Сохраните её при наличии таких потребителей; удаляйте только если других потребителей нет.
3. Без `TASK_ORCHESTRATOR_LOCALE` файл роли ищется в порядке `<role>.md` → `<role>.en.md` → `<role>.ru.md` → `<role>.zh.md` → первый `<role>.*.md`, а язык заголовков каталога skills — `en`. Значение `ru` сохраняет прежнее русское поведение.
4. Локаль Symfony-переводчика (`framework.default_locale`, `config/packages/translation.yaml`) — независимая стандартная настройка Symfony (`en`): она не следует за `APP_LOCALE` и не связана с локалью AI-ролей; меняется отдельно штатными средствами Symfony при отдельной необходимости.
5. Кеш: значение локали больше не запекается в скомпилированный контейнер — смена `TASK_ORCHESTRATOR_LOCALE` (например, `en` → `ru`) применяется со следующего запуска без ручной очистки кеша при том же корне кеша.

## Риски

- Наличие миграций данных: отсутствуют.
- Порядок применения миграций: не требуется; применяется только миграция окружения из раздела выше.
- Риск окна несовместимости: потребители, не добавившие `TASK_ORCHESTRATOR_LOCALE` (и рассчитывавшие на прежний `APP_LOCALE`), после обновления молча получат язык каталога по умолчанию (`en`) и порядок поиска ролей без приоритета `.ru.md` — миграция обязательна для всех русскоязычных host-проектов; после обновления рекомендуется контрольный запуск агентской цепочки.
- Риск полного обновления зависимостей (#381): `composer.lock` обновлён целиком, включая крупные переходы dev-инструментария (PHPUnit 10.5 → 13.3, Deptrac 2.0 → 4.7, coding-standard 0.32 → 0.33) и выравнивание runtime `symfony/*` на линию 8.1.x (ранее смесь 8.0.x и 8.1.0). Риск регрессий инструментария и различий окружений смягчён: непрерывная интеграция зелёная, #382 устранил notices/deprecations и включил защитные fail-флаги, `make check` пройден. При выявлении регрессии — восстановление через hotfix `v0.6.1` (см. ниже).
- Замечания по обратной совместимости: публичные CLI-команды, PHP-API и формат задач не менялись; меняется контракт конфигурации окружения (`APP_LOCALE` больше не действует).

## Порядок публикации

> Deploy (разворачивание) в терминах этого проекта — публикация тега из `main`; шаги «Web/Workers» из общего шаблона не применяются.

1. Убедиться, что подготовительный release PR с артефактами релиза слит в `main` и его обязательные проверки зелёные.
2. Убедиться, что `main` содержит только согласованный состав релиза: запросы #380, #381, #382 и артефакты `v0.6.0`.
3. Выполнить `make check`, `PHAR_EXPECTED_VERSION=dev make phar-smoke`, `make composer-host-smoke` на вершине `main`.
4. Создать тег `v0.6.0` на вершине `main` и отправить его через GitHub App.
5. Дождаться сценария `Release Phar`: он автоматически создаёт GitHub Release и загружает файл `task-orchestrator.phar`.
6. Проверить автоматически созданный GitHub Release; при необходимости обновить заметки через `gh release edit`, включив раздел «Миграция окружения».
7. Проверить опубликованный PHAR командой `php task-orchestrator.phar list`.

## Действия при проблеме после релиза

- Откат: не используется — тег релиза неизменяем.
- Стратегия исправления: hotfix (срочное исправление) от тега `v0.6.0` в ветку `hotfix/0.6.1-<short-description>`, обязательные проверки, запрос на слияние в `main`, публикация патч-тега `v0.6.1` с вершины `main` (сценарий `Release Phar` подхватит тег автоматически).
- Ответственный инженер: координацию hotfix ведёт Технический писатель Гермиона (pi); исполнителя назначает тимлид при заведении hotfix-задачи.
- Канал коммуникации и фиксации: `todo/` и запрос GitHub.
