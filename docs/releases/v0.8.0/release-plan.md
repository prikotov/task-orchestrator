# План релиза v0.8.0

## Метаданные

- Тег релиза: `v0.8.0`
- Тип повышения версии: `minor`
- Обоснование выбранной версии: расширение публичного CLI-контракта `agent:role-skills` (аргумент `<role|file>` и опция `--logical-pwd`) — новая совместимая функциональность; для серии `0.x` повышает `minor`
- База релиза: актуальная `main` (`17d1f92`) по `docs/releases/RELEASE-POLICY.md`
- Рабочая ветка подготовки: `task/release-v0-8-0`
- PR подготовки релиза: см. поле `pr` задачи `TASK-release-v0-8-0-preparation`
- Последний опубликованный тег: `v0.7.0`
- Ответственный: Тимлид Алекс (pi)
- Плановая дата публикации: 2026-09-17

## Состав

- [#393](https://github.com/prikotov/task-orchestrator/pull/393) — фикс запуска `become-role` в host-проектах: резолвинг пути к файлу роли по базисам (cwd, логический PWD с семантикой `cd -L`, корень host-проекта), явная диагностика «Файл роли не найден»; перенос резолвинга из bash в модуль `AgentRole` (PHP) с unit-покрытием; расширение CLI `agent:role-skills <role|file>` + `--logical-pwd`; `SKILL.md` по стандарту Agent Skills.
- [#394](https://github.com/prikotov/task-orchestrator/pull/394) — служебное: ретроспектива по фиксу и обновление реестра повторяющихся проблем (публичный контракт не меняет).

## Совместимость и известные ограничения

- Composer-канал и PHAR обратно совместимы: имя роли работает как раньше; опция `--logical-pwd` необязательна.
- Exit-код CLI при ненаходимом файле роли — по-прежнему `1` (fail-fast); текст диагностики изменён на явный.
- Внутренний контракт модуля `AgentRole` изменён (`ResolveRoleSkillsQuery.role` + `pathBases`, `ResolveRoleSkillsResultDto.roleName`) — модуль не является публичным API пакета.
- Миграции данных и новые обязательные переменные окружения отсутствуют.
- Host-проекты получают фикс после `composer update prikotov/task-orchestrator` (или обновления PHAR с повторным `agent:init`).

## Порядок публикации

1. Слить подготовительный PR в `main` после успешного CI, ревью и явного подтверждения merge.
2. Проверить, что коммит слияния совпадает по содержимому с одобренной веткой.
3. Выполнить проектные проверки на вершине `main`.
4. Создать и отправить тег `v0.8.0` на проверенный коммит слияния.
5. Дождаться workflow `Release Phar`, который создаст GitHub Release и загрузит `task-orchestrator.phar`.
6. Проверить опубликованный PHAR и описание выпуска.

## Проверки перед публикацией

- `composer validate --strict`
- `composer audit`
- `make check`
- `make composer-host-smoke`
- CI подготовительного PR успешен

## Проверки после публикации

- GitHub Release `v0.8.0` содержит непустой `task-orchestrator.phar`.
- `php task-orchestrator.phar --version` сообщает `0.8.0`.
- В host-проекте `bash .agents/skills/become-role/scripts/become-role.sh <role>` отрабатывает с первой попытки; путь к файлу роли с `../` от каталога скилла (после `cd` по симлинку) резолвится; несуществующий путь даёт явную диагностику.

## Действия при проблеме после релиза

- Откат и изменение опубликованного тега не используются.
- Исправление выпускается patch-релизом `v0.8.1` по проектной политике.
- Координация: задача в `todo/` и GitHub PR.
