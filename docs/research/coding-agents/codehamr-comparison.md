## Сводка

codehamr — это **минималистичный local-first терминальный агент кодинга на Go** (TUI на Bubble Tea): один бинарник, один протокол (OpenAI Responses API), один встроенный системный промпт, четыре инструмента (`bash`, `read_file`, `write_file`, `edit_file`) и ровно три slash-команды (`/models`, `/clear`, `/hamrpass`). Лицензия MIT. Автор позиционирует проект как «simplicity over complexity»: «no router, no sub-agents, no skill system, no MCP. That's it». Создан 2026-04-29, активно развивается (релизы с тегами-датами, последний — 2026-09-19).

Философия диаметрально противоположна расширяемости: системный промпт **зашит в бинарник** (`go:embed PROMPT_SYS.md`) и сознательно не выносится на диск («untamperable»); правилам проекта места в файлах нет — «Project specific rules go straight into the chat»; скиллов, AGENTS.md, сабагентов и per-command approval (подтверждений на каждую команду) не существует как класс. Расширяемость заменена одним инструментом `bash`: даже веб-поиск реализован не MCP-сервером, а инструкцией в промпте — поставить python-пакет `ddgs` и дергать его из bash, читать ссылки через `https://r.jina.ai/<url>`.

Ключевая особенность для нашего сценария: **headless-режима нет вообще**. `main.go` различает только `codehamr` (интерактивный TUI), `--version` и `--help`; флагов `-p`/`--print`, stdin-пайпа, JSON-вывода не существует. Агент спроектирован исключительно для человека за терминалом. Монетизация — опциональный предоплаченный HamrPass ($20, без подписки; для команд — «бюджет вместо мест», серверы в Германии под юрисдикцией ЕС), локальные модели остаются first-class (Ollama/vLLM/LM Studio, рекомендации по железу и сэмплингу в README).

## Критерий 1. Системный промпт

### Поведение

| Механизм | Поведение |
|----------|-----------|
| Встроенный промпт | `PROMPT_SYS.md` компилируется в бинарник (`//go:embed`); комментарий в `config.go`: «The prompt lives only in the binary, never on disk, so it's untamperable and every release ships it consistent». |
| Замена через CLI/env/config | ❌ Нет. CLI-флагов нет, env нет; схема конфига (`active`, `models`, `logging`) не содержит полей промпта, strict-декодирование отвергает неизвестные ключи. |
| Дополнение | ❌ Нет. Единственный способ добавить правила — написать их в чат («the conversation carries it»). |
| Fork | Пересборка бинарника с изменённым `PROMPT_SYS.md` — единственная точка замены. |

Сам промпт — тщательно спроектирован: цикл «вызов инструмента → отчёт», параллельные вызовы в одном сообщении, «не завершай ход, чтобы спросить», дисциплина верификации («A check must fail when the thing is broken», маркер `unverified:`), запрет публиковать секреты, минимальный код. Но это фиксированный артефакт релиза, а не настраиваемая поверхность.

### Сравнение с Pi

| Возможность | Pi | codehamr |
|-------------|-----|----------|
| Полная замена | `--system-prompt <text>` ✅ | ❌ (только пересборка) |
| Дополнение | `--append-system-prompt <text>` ✅ | ❌ |
| Файловая замена (проект) | `.pi/SYSTEM.md` | ❌ |
| Файловое дополнение | `.pi/APPEND_SYSTEM.md` | ❌ |

### Оценка: ❌ Не поддерживается

Хуже всех 24 исследованных агентов: ни CLI, ни env, ни конфига, ни файла. Для наших ролей (`docs/agents/roles/team/*.ru.md`) инъекция невозможна без форка проекта.

## Критерий 6. Запуск как сабагент (JSON-режим)

### CLI-surface

```bash
codehamr              # интерактивный TUI (единственный режим работы)
codehamr --version    # версия
codehamr --help       # справка: 3 slash-команды, клавиши, конфиг, env
```

| Аспект | Поведение |
|--------|-----------|
| JSON/JSONL-стрим событий | ❌ Нет. Нет `--print`/`-p`, `--output-format`, `--mode json`; stdin не читается. |
| One-shot / pipe | ❌ Нет. Единственный вход — человек в TUI. |
| Ephemeral | Двойственно: сессии вообще не персистятся (каждый запуск — чистый диалог), но headless-режима нет, поэтому для wrapper это не применимо. |
| Таймауты | ⚠️ Внутри TUI: bash-таймаут задаёт модель per-call (кап 3600s), idle-таймаут стрима; внешнего per-invocation таймаута не нужно — процесса-«вызова» нет. |
| События tool calls | ❌ Только рендер в TUI. |
| Автоматизация | Невозможна: эмуляция нажатий клавиш поверх TUI — не контракт. |

### Критические ограничения для сабагента

1. **Нет неинтерактивного режима вообще** — жёстче, чем у Zeroclaw/NanoClaw (gateway) и plain-text агентов (Hermes/Crush): там хотя бы stdout можно поймать, здесь вывод принадлежит TUI.
2. **Нет программного входа** — ни `-p`, ни stdin, ни RPC/ACP.
3. Компенсаций нет: наш `watch-subagent.sh`-контракт (события `agent_end`, `message_end`, tool events) и даже текстовый fallback непреализуемы.

### Оценка: ❌ Не поддерживается

**К6 — жёсткий блокер, худший результат исследования.** codehamr — единственный агент выборки, спроектированный исключительно для интерактивного использования.

## Вердикт

### ❌ Не подходит (Score: 4/10)

Сумма по 10 критериям: **16/30** (К1❌ К2❌ К3❌ К4❌ К5❌ К6❌ К7⚠️ К8✅ К9⚠️ К10✅ = 1+1+1+1+1+1+2+3+2+3 = 16). Уровень ZCode (17/30) и OpenClaw/NanoClaw (21/30, «не подходит»); ниже hax (23/30).

**Фундаментальная причина:** codehamr — не «агент с плохой автоматизацией», а **инструмент, сознательно спроектированный против автоматизации**: интерактивный TUI как единственный режим, непереназначаемый системный промпт, отсутствие контекстных файлов, скиллов и ролей. Всё, что делает его отличным молотком для человека с локальной моделью (минимальный контекст, нулевая конфигурация), одновременно исключает его из нашего сценария «сабагент под wrapper-контракт».

### Причины (по блокерам)

| # | Проблема | Влияние |
|---|----------|---------|
| 1 | **Нет headless-режима вообще** | К6: ни JSONL, ни one-shot, ни pipe — запуск из скрипта невозможен в принципе. |
| 2 | **Системный промпт зашит в бинарник** | К1: роли/инструкции не инъектируются; только форк и пересборка. |
| 3 | **Нет AGENTS.md / скиллов / ролей** | К2–К5: контекстная система проекта (конвенции, роли, скиллы) не подключается. |

### Сильные стороны (для других сценариев)

1. **Образцовая работа с контекстом локальной модели**: newest-first упаковка с якорем user-сообщения, понижение ранга (demotion) системных сообщений при переполнении, усечение вывода инструментов 1k+3k с маркером «PARTIAL view» и инструкцией, как восстановить пропущенное (grep полного файла), headroom-запас бюджета. Это самый продуманный context-packing среди минималистичных агентов исследования.
2. **Философия «prove it, don't promise it»** в системном промпте: запрет «false greens» (`|| true`, `2>/dev/null`), требование привязывать проверку к exit code, честный маркер `unverified:` в финальном отчёте. Это наш «контроль качества» в миниатюре — интересно как референс промптинга.
3. **Local-first инженерия**: документированные ловушки Ollama (тихая обрезка контекста, игнор penalty), рекомендации по сэмплингу и KV-cache, `X-Context-Window` для облачных профилей.
4. **Строгий конфиг**: strict-декодирование YAML (опечатки падают сразу), `${VAR}`-ссылки для ключей, перечитывание конфига перед каждой slash-командой (ручные правки живут без рестарта).
5. **Нулевой CLI-шум**: три команды и три клавиши — вся документация умещается на один экран.
6. **Честная монетизация**: опциональный предоплаченный пасс без подписки; ядро навсегда MIT/local.

### Паттерны для заимствования

| Паттерн | Описание |
|---------|----------|
| **Маркер усечения с планом восстановления** | Обрезая вывод инструмента (первые 1k + последние 3k токенов), codehamr не просто режет середину: маркер явно говорит модели — «это частичный вид, делать выводы по нему нельзя; если ниже назван файл с полным выводом — прочитай его (grep); иначе перезапусти команду в более узком виде (grep/sed/head/tail)». Инструкция восстановления встроена прямо в данные. |
| **`unverified:` в финальном отчёте** | Модель обязана лидировать сводкой непроверенного, если проверка не выполнялась — «честный отказ» вместо имитации доказательства. Полезно для наших ревью-циклов DynamicLoop. |
| **Запрет false greens в промпте** | Явный список антипаттернов (`|| true`, `2>/dev/null`, `# type: ignore`, удаление падающей проверки) — дешёвый способ поднять качество самопроверки агента. |
| **Параллельные вызовы в одном сообщении** | Промпт называет это «the biggest speed lever»: независимые вызовы одним раундом, зависимости — ждать результат; внутри сообщения вызовы упорядочены. |
| **Newest-first packing с якорем задачи** | При нехватке окна старое отбрасывается, но user-сообщение с задачей гарантируется в окне; системные сообщения при понижении ранга (demotion) не теряют валидность протокола. |
| **Строгий YAML + `${VAR}` для ключей** | Неизвестные ключи — ошибка запуска; секреты ссылаются на env, а не лежат в конфиге. |
| **Перечитывание конфига перед каждой командой** | Ручные правки конфига применимы без рестарта процесса; источник истины — файл, не память. |
