## Сводка

hax — это **минималистичный терминальный агент кодинга, написанный на чистом C**: один нативный бинарник, несколько МБ RAM, зависимости — только libcurl (HTTPS), jansson (JSON) и платформенные потоки; опционально `fzf` для `@file`-комплита. Лицензия MIT. Автор — Oleksandr Chekhovskyi. Проект молодой (создан 2026-04-24) и активно развивается: v0.4.0 от 2026-08-22, последний пуш — 2026-08-24. Позиционирование — «well-behaved Unix tool»: XDG-пути, чистый stdout в one-shot режиме, композициональность через сабпроцессы вместо плагинов.

Философия проекта зафиксирована в [docs/philosophy.md](https://github.com/OleksandrChekhovskyi/hax/blob/master/docs/philosophy.md) и радикально минималистична: **нет MCP, нет хуков и плагинов, нет per-command approval (запросов подтверждения на каждую команду), нет кастомных slash-команд**. Расширяемость — только через три «субстрата»: конфиг (`config.json`), markdown-файлы (`AGENTS.md`, `SKILL.md`) и сабпроцессы. Точка расширения для оркестрации — one-shot режим `hax -p`: скрипт снаружи управляет циклами, как в их же примере из документации:

```sh
hax -p "fix the failing tests"
until make tests; do
    hax -c -p "tests are still failing, keep fixing"
done
```

Это буквально паттерн нашего DynamicLoop (динамического цикла) — «оркестрация снаружи, а не хуки внутри».

**Ключевое отличие от Pi:** hax — полноценный автономный CLI-агент (не gateway-класс вроде OpenClaw/NanoClaw), но **без событийного JSONL-стрима**. One-shot контракт при этом сильнее, чем у большинства plain-text агентов: `hax -p` печатает финальный ответ ассистента **только в stdout**, а баннер провайдера, статистику, ошибки и resume-подсказку — **только в stderr**; есть ephemeral-режим `--no-session` и программное возобновление `--resume=ID -p`. То есть текстовый wrapper (обёртка) работает без «мусора» в stdout, но событийного мониторинга прогресса (tool calls) нет.

## Критерий 1. Системный промпт

### Возможности

| Механизм | Поведение |
|----------|-----------|
| `HAX_SYSTEM_PROMPT` (env) / `system_prompt` (config) | Полная замена базового промпта; принимает `@path` (файл) и специальное значение `(none)` — вообще не отправлять системное сообщение. |
| `HAX_SYSTEM_PROMPT_APPEND` (env) / `system_prompt_append` (config) | Дополнение к базовому промпту; тоже поддерживает `@path`. Документация рекомендует append вместо замены, чтобы сохранять встроенные safety-инструкции. |
| Пресеты в `config.json` | Именованный набор `provider`/`model`/`effort` + `system_prompt`/`system_prompt_append` + `tint` + `description`. Применение: `--preset=NAME`, `HAX_PRESET=NAME`, `/preset NAME`. |
| `--raw` (CLI) | Отправить только промпт: без системных секций, контекста и инструментов. |
| `--bare` (CLI) | Базовый промпт + Environment + инструменты, но без `AGENTS.md`/скиллов/делегирования. |
| `no_env`, `no_agents_md`, `no_skills`, `no_subagents` | Покомпонентное отключение секций контекста (env и config). |

CLI-флагов `--system-prompt`/`--append-system-prompt` **нет**, но env-механизм функционально эквивалентен для скриптового вызова: `HAX_SYSTEM_PROMPT_APPEND=@role.md hax -p "..."` задаёт промпт на конкретный запуск без изменения файлов (env в разрешении настроек выше `state.json`/`config.json`, но ниже явных CLI-флагов).

### Сравнение с Pi

| Возможность | Pi | hax |
|-------------|-----|-----|
| Полная замена | `--system-prompt <text>` ✅ | `HAX_SYSTEM_PROMPT` (env, `@path`, `(none)`) ⚠️ |
| Дополнение | `--append-system-prompt <text>` ✅ | `HAX_SYSTEM_PROMPT_APPEND` (env, `@path`) ⚠️ |
| Файловая замена (проект) | `.pi/SYSTEM.md` | Пресет в `config.json` (`system_prompt: @path`) |
| Файловое дополнение | `.pi/APPEND_SYSTEM.md` | Пресет (`system_prompt_append: @path`) |

### Оценка: ⚠️ Частичная поддержка

Полный набор операций (замена/дополнение/полное отключение) доступен программно через env и пресеты, что сильнее, чем у Crush/NanoClaw (только файлы конфигурации), но явных CLI-флагов нет — по классу эквивалентно Codex CLI (`model_instructions_file` в config). Для нашего wrapper-сценария приемлемо (env задаётся per-run), но менее эргономично, чем у Pi.

## Критерий 2. Промпт агента / Роль

### Подход — пресеты-как-роли

Роль в hax выражается **пресетом с описанием**: именованный набор провайдер/модель/effort/промпт. Только пресеты с полем `description` рекламируются модели как **цели делегирования** (subagent roles); «избранное» без описания остаётся личным ярлыком пользователя и модель его не видит (изменение v0.4.0: пресеты без description больше не приглашают к делегированию).

| Механизм | Назначение |
|----------|------------|
| Пресет с `description` | Именованная роль: свой провайдер/модель/effort/`system_prompt`(+append)/tint. |
| `--preset=NAME` / `HAX_PRESET` | Запуск агента в конкретной роли (в т.ч. в `-p` one-shot). |
| Делегирование | По явной просьбе модель запускает дополнительные `hax -p` как **управляемые фоновые задачи** (managed background tasks); наследуют provider/model/effort, либо уходят на пресетную роль. |

Изоляция ролей — процессная: каждый сабагент это отдельный `hax -p`-процесс со своим контекстом и (опционально) `--no-session`. Worktree-изоляции git (как у omp `task`) нет.

### Ограничения

1. Нет инъекции роли через позиционный CLI-аргумент — только пресет/env.
2. Роли описываются в `config.json` пользователя, а не в файлах проекта (наши `docs/agents/roles/team/*.ru.md` пришлось бы подключать через `system_prompt_append: @path` в пресете).
3. Внутренний планировщик сабагентов отсутствует — делегирование инициирует сама модель по просьбе, оркестрации «сверху» нет.

### Оценка: ⚠️ Частичная поддержка

Механизм ролей есть (пресеты + делегирование через фоновые `hax -p`), изоляция процессная, но конфигурация статична (файл конфигурации) и живёт в user-space, а не в проекте.

## Критерий 3. Скиллы

### Поведение

Скиллы — стандартный `SKILL.md` (формат agentskills.io): описание CLI/workflow и когда им пользоваться. В базовый промпт инжектируются **описания** скиллов; сам файл модель читает при необходимости (lazy). Философия: «скилл рассказывает модели, когда взять существующий CLI-инструмент» — вместо MCP-маркетплейнов.

| Аспект | Поведение |
|--------|-----------|
| Формат | `SKILL.md` ✅ |
| Проектная локация | `.agents/skills/<name>/SKILL.md` |
| Личная локация | `~/.config/hax/skills/<name>/SKILL.md` |
| Отключение | `no_skills` / `HAX_NO_SKILLS`, `--bare`, `--raw` |
| CLI-фильтрация | ❌ Нет `--skill <path>` / `--skills <glob>` — только «все или ничего» |
| Per-role наборы | ❌ Пресеты не фильтруют скиллы; набор определяется директорией проекта |

### Сравнение с Pi

| Возможность | Pi | hax |
|-------------|-----|-----|
| `SKILL.md` формат | ✅ | ✅ |
| `--skill <path>` | ✅ | ❌ |
| `--no-skills` | ✅ | ⚠️ `--bare`/`no_skills` (всё сразу) |
| Разным ролям — разные скиллы | ✅ через CLI | ❌ Все глобальны для проекта |

### Оценка: ⚠️ Частичная поддержка

Стандарт `SKILL.md` поддержан из коробки с автодискавери, но нет точечной CLI-фильтрации и per-role наборов — по классу как Qwen Code / OpenCode / Crush.

### Поведение

|----------|-----------|

Автообнаружение из CWD + глобальный уровень + иерархия внутри репозитория + полное отключение. Один из самых чистых вариантов среди исследованных агентов.

## Критерий 6. Запуск как сабагент (JSON-режим)

### CLI-surface

```bash
hax -p "fix the failing test"      # one-shot: финальный ответ → stdout
printf "explain x" | hax -p        # промпт из stdin
hax --no-session -p "..."          # ephemeral: не записывать сессию и историю
hax --resume=ID -p "next"          # программное возобновление конкретной сессии
hax -c -p "continue"               # продолжить последнюю сессию каталога
```

| Аспект | Поведение |
|--------|-----------|
| JSON/JSONL-стрим событий | ❌ Нет. Нет `--output-format`/`--json`/`--mode json` (проверено по `src/cli.c` и документации). |
| Чистота stdout | ✅ **Только финальный ответ ассистента в stdout**; провайдер-баннер, usage-статистика, ошибки, resume-подсказка — в stderr. Безопасно для pipe: `answer=$(hax -p "...")`. |
| Ephemeral | ✅ `--no-session` (+ `HAX_NO_SESSION=auto`). |
| Таймауты | ⚠️ Пер-invocation CLI-таймаута нет (внешний `timeout`); есть `max_turns` (лимит раундов модели), `bash.timeout` (2m, затем detach в фоновую задачу), `http.idle_timeout` (10m). |
| События tool calls | ❌ В stdout нет. Диагностика после факта: транскрипт Ctrl-T (`HAX_TRANSCRIPT` — зеркалирование model-facing контекста в файл), `HAX_TRACE` (HTTP/SSE-трассировка), JSONL-сессии в `~/.local/state/hax/` (история диалога). |
| Структурированный запрос модели JSON | Частично: `hax -p "produce JSON only" >result.json 2>run.log` — сам ответ модели может быть JSON, но это контракт с моделью, а не с агентом. |

### Критические ограничения для сабагента

1. **Нет событийного JSONL-стрима** — оркестратор не видит прогресс (tool calls, рассуждения) до финального ответа; наш `watch-subagent.sh`-контракт (события `agent_end`, `message_end`, tool events) не реализуем.
2. **Нет машинной телеметрии в stdout** — статистика токенов/стоимости идёт человекочитаемой строкой в stderr.
3. Компенсация для «ответ+JSON»-сценариев есть (чистый stdout), для мониторинга — нет.

### Оценка: ❌ Не поддерживается

**К6 — критический блокер остаётся.** При этом one-shot контракт hax — лучший среди plain-text агентов исследования (у Hermes/Crush «мусор» смешан с ответом или вывод вообще не для pipe): чистое разделение stdout/stderr + ephemeral + resume. Это «⚠️-уровень внутри ❌»: текстовый fallback-агент возможен, событийный мониторинг — нет.

## Критерий 7. Токены и стоимость

### Доступные метрики

| Механизм | Поведение |
|----------|-----------|
| Stats-строка после turn (stderr) | Elapsed time, использование контекста, spend; `~` — префикс оценочной (не точной) стоимости. |
| `/session` (REPL) | Локальные тоталы процесса по сессии. |
| `/usage` (REPL) | Аккаунт/подписка-уровень провайдера (ChatGPT, OpenCode Go), где поддерживается. |
| Каталог моделей | Кэш [models.dev](https://models.dev/api.json) (обновление 24h, фон); метаданные: контекст-лимиты, image-поддержка, цены input/output/cache_read за миллион токенов; `catalog.models` в config — per-model переопределение cost/limit. |
| Учёт в коде | `struct stream_usage`: `input_tokens`, `output_tokens`, `cached_tokens`, `cache_write_tokens` (+1h-вариант), `cost`; `agent_spend_account` аккумулирует по каждому turn и retry отдельно. |

Машинного извлечения (JSON) нет: данные есть внутри агента и в человекочитаемом выводе, программный парсинг stderr-строки хрупок.

### Оценка: ⚠️ Частичная поддержка

Полный внутренний учёт токенов и $-оценки (с разделением точной/оценочной), но нет программного API для извлечения — слабее Pi/omp (`cost` в JSONL), сильнее Crush (вообще ничего в stdout).

## Вердикт

### ⚠️ Частично подходит (Score: 6/10)

Сумма по 10 критериям: **23/30** (К1⚠️ К2⚠️ К3⚠️ К4✅ К5✅ К6❌ К7⚠️ К8✅ К9⚠️ К10✅ = 2+2+2+3+3+1+2+3+2+3 = 23). Уровень Zeroclaw (23/30) и Codebuff (23/30).

**Фундаментальная причина:** hax — настоящий автономный CLI-агент (не gateway-класс), и его one-shot контракт — лучший среди plain-text агентов исследования, но **событийного JSONL-стрима нет и не планируется** — это осознанное архитектурное решение философии («инспектируемость через транскрипты после факта, а не события в полёте»). Для нашего сценария «сабагент под `watch-subagent`-контрактом» К6 не закрыт.

### Причины (по блокерам)

| # | Проблема | Влияние |
|---|----------|---------|
| 1 | **Нет JSON/JSONL-стрима событий** | Мониторинг прогресса сабагента (tool calls, `message_end`) невозможен; только финальный текст в stdout. |
| 2 | **Нет машинной телеметрии** | Токены/$ только человекочитаемой строкой в stderr; программный парсинг хрупок. |
| 3 | **Нет CLI-флагов промпта** | Только env (`HAX_SYSTEM_PROMPT`/`_APPEND`) и пресеты — для wrapper-скрипта приемлемо, но не контракт уровня Pi. |

### Сильные стороны (для других сценариев)

1. **Лучший one-shot контракт plain-text класса**: чистый stdout / вся диагностика в stderr / `--no-session` / `--resume=ID -p` / промпт из stdin — готовый текстовый fallback-агент для wrapper без JSONL.
2. **Минимальный footprint**: нативный C-бинарник в несколько МБ RAM — единственный агент исследования, спроектированный «оставить память локальной модели».
3. **Локальные модели first-class**: llama.cpp с авто-обнаружением и multi-model router (показывает каталог моделей сервера и их load state, прогревает выбранную).
4. **Пресеты-как-роли** с осмысленным гейтом делегирования (только описанные пресеты рекламируются модели).
5. **Чистые стандартные поверхности**: `AGENTS.md`-иерархия + `.agents/skills/` + `SKILL.md` — интеграция контекста без конвертации.
6. **Инспектируемость**: транскрипт model-facing контекста (Ctrl-T/`HAX_TRANSCRIPT`), HTTP/SSE-трассировка (`HAX_TRACE`), plain-text JSONL-сессии.
7. **Spend-учёт** с каталогом models.dev и per-model переопределениями цен; честная маркировка оценочной стоимости `~`.
8. **Философская близость**: «оркестрация снаружи скриптами, а не хуки внутри» — их канонический пример цикла `until make tests; do hax -c -p ...; done` это наш DynamicLoop.

### Паттерны для заимствования

| Паттерн | Описание |
|---------|----------|
| **Пресет-как-роль с гейтом описания** | Делегирование предлагается модели только для ролей с осмысленным `description`; «избранное» пользователя моделью не видно. Решает проблему шумного делегирования по имени. |
| **Чистый stdout / диагностика в stderr** | Контракт one-shot: ответ — только stdout, баннеры/статистика/подсказки — только stderr. Эталон для всех текстовых fallback-агентов. |
| **config.json vs state.json** | Портативная конфигурация (dotfiles, версия в git) отделена от машино-локального состояния (интерактивные выборы). Интерактив не портит переносимый конфиг. |
| **Каталог моделей + per-model override цен** | Кэш models.dev с переопределениями `catalog.models` (cost/limit per model) даёт $-оценку без биллинга провайдера; `~` маркирует оценочное. |
| **Bash-timeout с detach** | Команда, не уложившаяся в `bash.timeout`, не убивается, а отцепляется в управляемую фоновую задачу (`/tasks`, `task.wait_timeout`, `task.max_running`) — модель может вернуться к результату. |
| **Иерархия разрешений настроек** | `CLI-флаг → resumed-сессия → env → state.json → config.json → default`; возобновлённая сессия помнит свой провайдер/модель — «слои» не перемешиваются. |
| **`(none)` для системного промпта** | Трёхзначная семантика: значение / пусто / `(none)`-токен «вообще без системного сообщения» — точнее, чем пустая строка. |

## Приложение А. Сравнение с Pi по ключевым критериям

| Критерий | Pi | hax |
|----------|-----|-----|
| Тип | CLI-coding agent (Node.js) | CLI-coding agent (нативный C) |
| JSON-режим | `--mode json` (JSONL) | ❌ Нет (чистый текстовый stdout) |
| Ephemeral | `--no-session` | ✅ `--no-session` |
| System prompt (CLI) | `--system-prompt` + `--append-system-prompt` | ⚠️ `HAX_SYSTEM_PROMPT`(+`_APPEND`) env / пресеты |
| Skills (CLI) | `--skill` + `--no-skills` | ❌ Только `no_skills`/`--bare` (всё или ничего) |
| AGENTS.md | Автообнаружение из CWD | ✅ Автообнаружение + глобальный + иерархия git-корень→cwd |
| `.agents/skills/` | ✅ | ✅ (+ `~/.config/hax/skills/`) |
| Pipe-управление | `--mode rpc` через stdin/stdout | ❌ Только one-shot `-p` (+ `--resume=ID -p`) |
| Контроль таймаутов | wrapper | `max_turns`, `bash.timeout`, `http.idle_timeout`; per-invocation — внешний |
| Токены/$ | ✅ Полная + `cost` в JSONL | ⚠️ Stats-строка stderr, `$` по каталогу; машинного API нет |
| Провайдеры | 20+ | 10 + custom-блоки |
| Локальные модели | ✅ | ✅ First-class (лучший UX в исследовании) |
| Лицензия | MIT | MIT |
